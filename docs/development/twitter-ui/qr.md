# 二维码页面与设备边界

`/settings/profile`、本人用户菜单与二维码导航项均进入既有 `/qr` 路由。二维码页面属于 P-11 的可见子路径，不需要单独的业务路由或状态仓库。

## 页面表现

Twitter UI 复用 `TwitterSettingsShell` 的标题与返回操作。显示、扫描两个页签支持方向键及 Home / End；扫描视图离开时释放摄像头。显示视图使用 Twitter 设计变量排版头像、账号和二维码说明，系统支持 Web Share 时提供显式分享按钮。

二维码内容仍为实例规范 URL 下的 `/users/:id`，分享链接沿用既有资料页生成规则。中心图标表示当前实例；Twitter 变体不展示固定 Misskey 字样、点阵或设备翻转效果。默认 UI 保留原二维码配色及翻转交互。

画布使用固定深色码点和浅色静区，分别来自 `--twitter-qr-fg`、`--twitter-qr-bg`。这两个变量在明暗主题中保持一致；页面先取得已解析的元素颜色，再将实际颜色写入 Canvas。不得将未解析的 CSS `var()` 或 `light-dark()` 表达式直接交给二维码库。

## 摄像头与图片识别

`utility/qr-camera.ts` 是浏览器设备访问边界。模块只在实际操作时申请、枚举或释放媒体流；扫描只申请视频，不申请麦克风。默认使用浏览器选择的可用摄像头，用户指定设备时使用精确设备约束。枚举设备和读取闪光灯能力不额外申请媒体流。

`qr.read.vue` 先通过适配器取得原生媒体流，再将其附给视频元素并启动 `QrScanner` 解码。原生设备错误保留至页面边界，不经扫码库的开流重试转换为统一英文字符串。

摄像头不可用或暂停时，Twitter 变体显示由图标、标题和恢复说明组成的紧凑状态卡；视频元素仍常驻，正常开流后使用视频预览区域。图片入口为文字主按钮，摄像头操作组保持整体并自然换行；间距、配色、触控尺寸来自已有 Twitter 设计变量。

### 操作能力

按钮可用性从本次会话的摄像头状态和公开设备清单派生，基础按钮使用原生 `disabled`。未知设备清单为 `null`，与空清单分开；单摄像头和未知清单都不提供镜头选择。能力说明直接显示在操作栏旁，不仅依靠悬浮提示。

| 当前事实 | 启动与恢复 | 切换镜头 |
| --- | --- | --- |
| 非安全上下文或媒体 API 不可用 | 禁用启动，显示原因和图片入口 | 禁用 |
| 正在启动 | 可取消当前启动 | 禁用 |
| 已确认无设备 | 禁用启动，提供重新检测；检测到设备后由用户手动启动 | 禁用 |
| 权限拒绝 | 引导调整权限，保留显式重试 | 禁用 |
| 设备占用、读取失败或约束失败 | 保留重试；失效的选择在清单更新后清除 | 有多个已公开选择时可切换 |
| 正常运行或主动暂停 | 运行时可暂停，暂停后可重新启动 | 至少两个有效设备标识时可切换 |
| 设备枚举失败 | 健康视频流继续工作，提供重新检测 | 禁用 |

成功取得摄像头后刷新设备清单，使授权后公开的设备信息参与按钮能力判断。设备变化、手动重新检测以及此前已暂停或错误时的页面恢复可见只枚举设备；这些路径不另开媒体流。清单不等同于物理设备总数，空标识不能作为精确镜头约束。摄像头启动明确失败为无设备时，后续检测或设备事件才能恢复启动能力。

非安全局域网 HTTP 来源不能通过修改页面样式取得浏览器禁止授予的摄像头权限。前端在此来源下显示准确状态；实际摄像头使用需要浏览器认可的安全上下文。

### 完成结果与处理中状态

图片解码不依赖摄像头授权，继续使用 `QrScanner.scanImage`。选图取消不会显示识别进度；选到文件之后区分图片解码与内容解析，并在任务完成前抑制重复上传。摄像头错误不会禁用图片入口。

原始文本解码成功即可提交完成结果；URL 等待真实 `ap/show` 归类，成功时先更新用户或帖子列表再提交完成结果，不能解析为联邦对象时提交原始 URL。首次完成结果之前，整个用户 / 帖子 / 全部结果区不挂载，解析期间仅显示轻量进度。没有二维码或图片解码失败不会展开首次结果区，已有结果也不因后续识别失败而消失。

进行中的 URL 请求按原始内容合并，已完成内容不重复解析。实体列表保留最多三十个最近归类 URI；只有完成归类时统一更新列表。首次结果选择对应分类，后续较早请求与重复帧不能覆盖较新结果的分类；用户主动切换后，之前发起的请求也不能抢回页签。切到尚无对应内容的分类时显示该分类的简短空态。

## 生命周期

每个扫描视图只创建一个解码器实例。停止时先取消当前轨道的结束监听，再立即暂停解码器、停止其活动状态并释放媒体轨道；离页和 KeepAlive 失活走相同清理路径。每次启动带有本地递增令牌，迟到成功只能释放自己的流，不得附着到新视图或更改新请求状态。

页面可见性监听使用捕获阶段，隐藏时先关闭解码器的活动状态，防止库自行重开摄像头。此前正在运行或启动的扫描在重新可见时通过适配器恢复；用户主动暂停和已有不可用原因保持原态。资源释放不会把设备错误误改为可重新启动的暂停状态。

设备变化订阅与当前活动视图一起绑定和解绑。轨道自然结束时立即停止解码及释放旧流，重新枚举后区分当前无设备与可重试读取失败；不自动开启替代摄像头。开启闪光灯只操作现有轨道，关闭时通过同一受控启动流程释放并重开摄像头，避免绕过适配器。

视图失活时使未完成的图片解码与 URL 归类失效，保留已经完成的结果。迟到响应不得提交到后来恢复的会话，也不能删除新会话对同一内容的进行中请求。

## 验证入口

- `test/unit/qr-camera.test.ts`：适配器权限参数、能力分类、原始错误保留、枚举、设备变化 / 轨道结束订阅清理以及轨道释放协议。
- `test/e2e/qr.spec.ts`：真实资料设置入口、实际 Canvas 图片识别、真实 `ap/show` 归一化与延迟结果挂载、中文摄像头反馈和按钮能力、真实浏览器流的暂停 / 离页释放，以及迟到旧流不覆盖新流。
- 视觉采样覆盖桌面 / 移动、明 / 暗两组轴；输出图片供人工检查，不将本次截图自动宣布为批准基线。

端到端测试由外部流程提供隔离测试实例，默认 `QR_E2E_ORIGIN=http://localhost:61812`，规范地址通过 `QR_TEST_CANONICAL_URL` 指定。局域网 HTTP 轮次使用 `QR_E2E_INSECURE=1`，视觉采样使用 `QR_E2E_SCREENSHOTS=1`。安全上下文轮次需在外部 Playwright 配置中启用 Chromium 的测试摄像头；测试边界探针只控制媒体回执，业务接口使用真实后端。

原生可见性用例使用 `@native-visibility` 标记，由外部流程提供独立 Chromium 的 `QR_E2E_NATIVE_CDP` 连接地址。该浏览器应使用独立用户目录，首次连接即通过 `connectOverCDP` 的 `noDefaults: true` 保留默认上下文的原生可见性；测试以实际标签页切换验证隐藏与恢复，不覆盖 `document.hidden` 或派发模拟事件。未提供连接地址时只跳过这些原生生命周期用例，普通 HTTP、权限、暂停和结果识别用例照常执行。浏览器的启动与清理由外部流程负责。

测试代码不负责启动基础设施，也不探测数据库或部署身份。`resetState` 只可指向隔离测试实例。
