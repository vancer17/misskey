# Twitter UI 帖子附件布局

## 范围与所有权

Twitter 帖子卡片、详情主帖及线程行统一通过 `ui/twitter/components/TwitterNoteMedia.vue` 展示附件，由 `ui/twitter/index.ts` 对外导出。包装组件向一个完整的 `MkMediaList` 提供横条展示参数，并转发 `openGallery(id?)`；整帖继续共用一个灯箱及原有附件顺序。

附件模型、敏感内容判断、揭示状态、加载权限、菜单、音视频控制及灯箱由既有 Misskey 组件负责。新增尺寸与滚动状态只服务当前渲染，不修改附件模型，不持久化，不新增业务 Store，也不参与请求或权限决策。音频与不可预览附件继续使用原组件及其既有行为。

## 尺寸契约

图片及视频保持原始宽高比，附件框本身匹配内容比例。单附件沿正文起点放置；多个附件保持同一行、顶部对齐、`4px` 间距，并允许横向溢出。轨道高度由当前最高附件决定，较矮附件下方沿用帖子表面，不额外绘制条纹或黑色填充带。

设正文可用宽度为 `C`，有效宽高比为 `r`，当前高度上限为 `H`：

```text
显示宽度 = min(C, H × r)
显示高度 = 显示宽度 ÷ r
```

高度上限使用 Nitter `media.scss` 的 `379.5px`，同时保留当前半视口高度约束。尺度由 CSS 与容器几何提供，不在组件中新增设备探测。旧的单图固定比例、`n1/n2/n3/n4/nMany` 网格类及宽区方格偏好不参与横条布局。

长截图与全景图保留完整内容，通过灯箱查看细节；不以统一裁切或强制最小高度补齐尺寸。透明图片由主题表面承托。原文件自带的黑边属于内容，不作自动裁边。敏感内容遮罩、加载占位及媒体自身控制层保持其既有用途。

## 尺寸来源与加载边界

只读几何定义与计算集中于 `ui/twitter/domain/media-layout.ts`，从原有附件信息单向派生，不复制 `DriveFile` 或帖子业务类型。每项通过 `--media-aspect-ratio` 向 `MkMediaList` 提供比例；高度上限由 `--twitter-media-max-height: min(379.5px, 50svh)` 提供，附件圆角消费既有 `--twitter-radius-large`（`16px`）。

1. 优先使用附件中有效、有限且大于零的宽高元数据。
2. 元数据缺失时，消费当前权限已允许加载的图片或视频封面自然尺寸。
3. 视频没有可用封面尺寸时，消费现有视频元素的 `loadedmetadata`。
4. 尚无有效尺寸时保持中性占位；尺寸到达后仅更新对应附件的临时几何。

尺寸事件关联当前附件及资源，资源切换后到达的旧回调不能覆盖新资源。敏感隐藏、省流及尚未允许加载的附件不为测量额外创建图片、视频或网络请求。读取已加载资源的尺寸不回写原附件，也不把加载结果提升为业务事实。

## 横向交互

轨道采用原生横向滚动、`scroll-snap-type: x proximity` 与 `overscroll-behavior-x: contain`；附件项不收缩。手指横滑与触摸板横滚作用于附件轨道，普通纵向滚动继续交给时间线。

仅在内容溢出时于轨道下方提供前后导航按钮，并根据真实滚动位置处理边界。按钮具有可访问名称及键盘焦点，轨道自身聚焦时支持左右方向键；关闭动画或启用减少动态效果时直接到达目标位置。轨道与按钮的几何状态不复制附件业务集合。

轻点继续打开对应附件，横滑不能触发帖子详情导航或灯箱。三处帖子入口共用完整图库，列表与详情主帖保留原有 `o` 灯箱快捷键；包装层不得把附件拆成多个独立图库。媒体外层裁切不得截断横向导航按钮及可见焦点轮廓。

## 来源与验证边界

尺度来自 `external/app/nitter/src/sass/tweet/media.scss`：媒体上限 `379.5px`、附件间距约 `0.25em`。Nitter 自身会分行，部分媒体采用裁切；其 `533px` 是宽度上限。本项目沿用正文容器宽度，原 Twitter 媒体外框的 `16px` 圆角改由各附件承接；横条及完整保留内容属于 [ADR-0030](./adr/0030-proportional-media-strip.md) 记录的产品选择。

此前桌面探测的 [X 四图帖子](https://x.com/NASA/status/2046969982131507400)呈现横向 flex、`overflow-x: auto`、`4px` 间距、滚动吸附及导航按钮，图片使用 `cover`。该样本仅支持桌面页面的对应观察，不证明 X 移动端行为，也不把本项目的完整保留内容策略归为 X 实测结论。

专项验证覆盖单附件、多附件、混合图片与视频、长截图、透明图、缺失尺寸、敏感隐藏／揭示、省流和加载失败，并检查窄屏、桌面、明暗主题及动画偏好。尺寸、单行、末项可达、页面无横向溢出、滑动与点击区分、灯箱顺序及视频播放分别验证。真实业务链路使用独立后端测试实例，Mock 仅证明协议、序列化和适配映射。

截图 diff 固定数据、视口、DPR、缩放、字体和主题；实际通过情况以交付记录为准。局部截图与专项测试不自动建立或替代 P-19 全站视觉基线。
