# Twitter 首页时间线正文与加载转场

## 范围与事实来源

首页时间线的来源切换由 `TimelineShell` 及其 `useTwitterTimelineTransition` 协调正文横移和主滚动位置，`TwitterStreamingTimeline` 的加载边界负责初始加载交接。标签指示条仍由 [共享标签指示条](./tab-indicator-motion.md) 负责。两者跟随同一个已提交来源，各自只处理展示，不等待动画结束再提交来源或发出请求。

`pages/timeline.vue` 沿用原 `v-model` 来源和账户、来源、筛选组成的完整查询 key，不增加第二份切换状态。`TwitterStreamingTimeline` 继续注入唯一的 `TwitterTimelinePaginator`；来源变化销毁旧查询所有者，新来源立即开始首拉。接口映射、分页、实时订阅、轮询、新帖队列、删除处理和 [手动刷新](./timeline-refresh.md) 保持原归属。

本功能不为各来源建立持久列表缓存或位置表，不保存帖子数组副本，不从 DOM、帖子数量或接口原始响应重新判断加载事实。通知、频道和个人资料正文不接入此首页专用交接。

## 点击动画与手势

多个来源可切换时，时间线壳使用同一个 `MkSwiper` 负责正文横向过渡。点击切换不依赖“启用横向滑动”；触摸识别及 `pan-y pinch-zoom` 限制只在该偏好开启时应用，关闭时保留浏览器原生平移行为。正文动画遵守 Misskey 动画偏好和 `prefers-reduced-motion`，关闭后直接进入正确终态。

`MkSwiper` 的扩展提供可选展示参数、过渡生命周期事件、离场结算入口和时长／缓动／间隔 CSS 参数。Twitter 使用既有正常时长 `180ms`、`--twitter-ease` 和零额外横向间隔；未指定的消费者沿用原默认值。正文不再嵌套第二个横移层，不通过动画结束事件驱动业务请求。

离场完成使用 Vue 公开 `leave` 回调；样式提交后仅读取面板自身动画的真实结束信号，不等待后代骨架或媒体动画。壳在下一次来源提交前调用公开的 `finishLeaving()` 结算旧离场，即使浏览器尚未建立 CSS 动画，也能让 Vue 完成旧节点清理；不读取 Vue 私有字段或直接删除 DOM。

## 加载交接

`TwitterTimelineLoadBoundary` 直接接收 `TwitterStreamingTimeline` 从查询所有者派生的 `initializing`。共享 `MkStreamingNotesTimeline` 提供有默认内容的 `loading` 插槽；Twitter 包装层使用空插槽，将骨架交给边界绘制，实际列表仍只有一份。

| 阶段 | 呈现 |
| --- | --- |
| 首拉开始 | 列表立即挂载和请求，骨架延显计时开始 |
| 在快速时长 `120ms` 内完成 | 取消骨架任务，显示真实结果 |
| 超过延显阈值 | 骨架覆盖层淡入 |
| 首拉完成 | 原组件显示帖子、空态或错误，结果淡入、骨架淡出 |
| 骨架淡入途中完成 | 从当前透明度转向完成态，不强制显示完整骨架周期 |
| 动画关闭或减少动态效果 | 直接交接终态 |

延显只控制加载反馈，不延迟请求、设置最短骨架停留时间或等待正文横移结束。骨架是不可交互的展示覆盖层；空态、失败和重试继续由原列表及其查询所有者决定。

## 来源切换与滚动

来源切换采用新来源回顶策略；离开／回访时间线路由仍使用 [Shell 位置恢复](./scroll-layout.md)。同标签重选和手动刷新保留各自现有入口，不借用请求完成事件再次回顶。

切换时先测量旧正文的可见区域及相对主视口位置，再把 Vue 已有的离场 DOM 冻结为短暂视觉层。旧组件仍正常卸载并释放查询、订阅和监听；离场 DOM 设为 `inert`、`aria-hidden` 且不接收指针，不复制实体或克隆内容树。主 Shell 捕获路由恢复锚点时排除离场层，转场中立即离页也不会把旧来源片段记录为新来源位置。

随后通过 `useTwitterSourceScrollReset` 取消主 Shell 当前待恢复任务并立即重置真实滚动宿主；该公开接口只返回当前活动 DOM 是否接纳操作，不暴露宿主或位置表。旧视觉层用 CSS 个体 `translate` 补偿重置产生的纵向位移，`MkSwiper` 继续独占横向 `transform`；旧层显示切换前可见的帖子片段，新来源从顶部进入。临时几何围绕当前可见正文区域建立，不保留整个旧列表高度。

快速切换合并到最新目标，旧动画结束回调及计时器不能清理新交接的约束。完成、取消、页面失活或卸载均释放临时 DOM 约束和任务；用户开始滚动后，迟到网络响应不能再次移动主宿主。独立页面窗口继续使用自己的真实滚动容器，不访问 Shell 的位置表。其原 keeper 只增加待恢复任务的取消入口；来源切换先作废旧代次的 `nextTick` 和延迟恢复，再立即回顶，正常缓存回访继续使用既有锚点算法。

## 验证边界

`packages/frontend/test/e2e/twitter-timeline-transition.spec.ts` 为正文转场的真实浏览器回归入口。正文转场需要独立检查开始、中间、结束帧，不能用标签指示条动画或静态终态截图代替。加载用例分别覆盖快响应、延显阈值附近响应、慢响应、空态、失败与重试；通过传输闸门延迟真实请求，不伪造业务响应。

深滚动用例从 `700px` 位置切换，记录正文几何、离场可见片段、宿主 `scrollTop` 和可滚动高度，确认回顶仅发生于来源提交阶段。还需覆盖快速往返切源、旧响应晚到、用户接管滚动、缓存回访、路由恢复、同标签重选、手动刷新及独立窗口。

测试通过、失败和未执行的平台以本次交付报告为准；代码中存在用例或局部截图不代表已经通过，也不自动批准阶段正式视觉基线。方案理由与被替代做法见 [ADR-0028](./adr/0028-timeline-body-loading-motion.md)。
