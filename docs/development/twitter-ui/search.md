# Twitter UI 搜索

## 状态与数据所有权

`pages/search.vue` 根据现有 UI 风格选择展示容器，并将路由解析后的简单参数与既有策略传给 `TwitterSearch.vue`。Twitter 搜索标签的权威取值来自 `ui/twitter/domain/search.ts`；容器从 `props.type` 只读派生选中标签，不保存第二份已提交标签。输入框仅保留未提交的临时草稿，提交后的关键词与筛选由路由驱动。

常驻搜索框通过当前注入路由的 `currentRef.value.props.get('query')` 恢复实际关键词。路由定义中的 `q: 'query'` 仅声明字段映射，不作为用户输入。离开搜索页时保留搜索框草稿，不将其他页面路由误读为搜索文本。

帖子、用户搜索入口分别消费 `utility/check-permissions.ts` 导出的只读 `computed`：登录时使用账户策略，访客使用实例策略，跟随现有资料加载与更新重新派生。帖子搜索是否授权、用户搜索是否授权相互独立；最终授权仍由对应后端接口执行，前端不硬编码角色默认值，也不探测搜索引擎来决定权限。

## 路由与加载边界

`/search` 使用固定 `viewKey: 'search'`，普通出口复用原有 `RouterView` 能力。页内修改关键词、标签或来源时更新同一搜索页实例；默认 Misskey 界面同步路由传入的标签，保留原有手动搜索。

Twitter 实验叠层出口由宿主提供 `stableViewPath="/search"`。同一路径的导航仅原位更新当前卡片的已解析 props 与完整地址，保留该卡片的展示键；历史卡片不按搜索路径统一合并。离开后重新创建的搜索卡片使用独立展示键，其他页面继续使用既有叠层匹配与缓存机制。共享出口只处理展示身份，不解析搜索业务或权限。

常驻搜索发起导航使用 `push`；搜索页内提交、标签及来源切换使用 `replace`。序列化仅包含有效的简单字段，不输出字面量 `undefined` 或 `null`，不将完整实体写入 URL。标签选中、结果参数和地址由同一提交后的路由派生，单击不先写入局部标签副本。

搜索框、标签栏和来源栏位于稳定页头。结果区域内的 `Suspense` 承接搜索模块代码等待；查询期间的加载、空结果、错误和重试由结果组件及原分页组件呈现。结果切换不能撤下整个页头。键盘方向键、Home、End 与点击共用同一标签导航流程；每个搜索实例使用独立 ARIA 标识，焦点仅在当前标签栏内移动。

URL 查找沿用既有 AP 解析服务。新导航、关键词变化、组件停用或卸载会撤销旧查找的导航资格；叠层中仍挂载的历史搜索卡片也不能用迟到结果改变当前页面。

## 搜索结果控件

话题快捷入口及其容器仅在“帖子”标签挂载，依据路由只读派生的当前标签控制；切回“帖子”时恢复显示。“用户”标签继续将原始关键词（如 `#test`）提交给 `users/search`，用户结果简介中的真实话题标签内容照常呈现。`@用户` 与 URL 快捷提示沿用原有展示和导航行为。

Twitter 自动搜索不挂载原生“选项”表单，包括起止时间、搜索范围、主机输入及用户选择控件。帖子结果保留原有 `MkNotesTimeline` 分页工具条：排序选择、日期定位和刷新仍交给当前分页器处理。日期定位通过 `initialDate` 映射为 `sinceDate` 或 `untilDate`，用于分页起点，不表示双边时间范围。

默认 Misskey 手动搜索保留完整原生表单及提交方式。表单的 `rangeStartAt`、`rangeEndAt` 仅参与手动搜索请求；Twitter 自动请求不读取或发送这两个字段。既有路由 `userId`、`username`、`host` 仍作为完整搜索条件解析，界面未显示对应表单不改变这些条件、权限检查或解析失败时禁止放宽范围的规则。

## 查询生命周期

`pages/search.note.vue` 将 `query`、`userId`、`username`、`host` 作为整组已提交条件同步。用户筛选先经 `users/show` 解析，再交给 `notes/search`；用户标识优先，标识解析失败不会改用另一个身份或无用户条件。新条件到达或组件卸载时取消旧解析，已取消的结果没有提交资格。

主机条件复用同一规范化函数。本地标识 `.` 与实际本地主机在 `users/show` 请求中省略 `host`，在帖子搜索请求中映射为 `.`；远端主机保留规范化值。用户解析失败、远端用户不在实例允许范围内、显式远端主机与仅本地搜索范围冲突时，保持局部错误并阻断帖子查询，不自动放宽范围。默认 Misskey 的筛选表单在解析期间暂停交互；用户主动调整筛选后仍需通过完整参数校验。

`pages/search.user.vue` 同批同步关键词与来源，随后派生完整请求，避免旧来源与新关键词组成中间请求。自动模式在关键词、筛选或来源改变时更换原有 `Paginator`；默认界面的手动模式在外部路由更新时清除旧结果，等待用户提交，不因临时表单编辑自动取数。列表挂载负责首次加载，页面不额外调用 `init()`。旧分页器的迟到响应仅属于旧所有者，不能进入当前结果集合。

搜索结果仍由各自的原分页器唯一持有，页面不复制条目，不额外引入 Store 或查询框架。关键词草稿、路由筛选解析、请求取消与加载状态服务当前交互；默认 Misskey 另保留局部筛选表单，均不替代领域事实。业务组件和领域模块不导入环境配置加载、服务探测、readiness 或制品识别实现。

## 搜索服务与权限运维

前端显示“帖子检索不可用”表示当前策略不允许帖子搜索，不能据此判断没有匹配内容。应通过当前账户资料与既有角色管理核对有效的 `canSearchNotes`，并由实际 `notes/search` 请求确认授权。公开实例策略不能替代登录账户的最终策略；角色变更后按现有会话机制更新账户资料。

后端按 `fulltextSearch.provider` 选择部署提供方。选择 Meilisearch 时，需要分别确认服务可用、索引任务成功及真实检索命中；服务恢复不等于历史帖子已入索引。仅操作搜索服务，不通过包含数据库和 Redis 的整套快捷编排替换已有服务或数据卷。

以下 `systemctl` 命令仅是采用该服务名的本地 systemd 部署示例，不假定其他环境已安装该服务。其他环境使用其既有进程或容器管理方式，并固定兼容版本、持久化路径及认证配置。

```bash
sudo systemctl status misskey-meilisearch --no-pager
sudo systemctl restart misskey-meilisearch
```

修改受忽略配置文件中的提供方或连接配置后，需要编译后端配置，并通过当前部署的正常管理入口重启后端。配置文件修改不依靠前端热更新生效；认证值只保留在受控配置中，不写入文档、命令输出、测试截图或 Git。

```bash
corepack pnpm --filter backend compile-config
```

已有 `sqlLike` 可作为明确选择的部署提供方。切换后同样编译配置并正常重启后端；它不是前端 feature flag，也不在 Meilisearch 故障时自动启用。搜索服务故障由实际请求的错误状态反馈，不伪装成权限关闭或空结果。

## 历史帖子索引回填

仓库 CLI 提供 `backfill-note-search`，要求当前配置使用 Meilisearch 且服务可达。命令通过既有 `SearchService.indexNote()` 复用索引资格、范围与文档映射，不增加另一套帖子规则。

执行流程如下：

1. 在维护期暂停所有节点上的帖子写入，包括创建、编辑、删除、联邦入站与相关队列任务，等待在途帖子写入结束。保持暂停直到本轮索引任务全部成功；命令本身不负责建立或检查维护屏障。
2. 确认搜索服务及持久卷正确，使用部署已有的受控管理通道记录索引任务边界。构建当前后端，使新增 CLI 进入制品。
3. 在仓库根目录使用目标部署的受控配置执行下列命令。CLI 自身会编译配置；不得将认证值直接拼入命令。
4. 命令返回后，继续暂停写入。通过搜索引擎管理接口检查本轮索引设置及文档提交对应的异步任务均为 `succeeded`，处理失败任务，并用符合当前索引范围的历史帖子验证实际搜索命中。
5. 确认任务成功与实际命中后，恢复帖子写入，并验证新帖的正常增量入索引。

```bash
corepack pnpm --filter backend build
corepack pnpm --filter backend cli backfill-note-search
```

回填开始时取得当前最大帖子 ID 作为固定上界，按升序 ID 游标每批扫描 100 条；符合现有规则的文档按帖子 ID 幂等提交。固定上界使扫描有界，不是数据库快照，不能防止并发编辑或删除，因此不能省略维护屏障。

命令只等待索引提交，不等待 Meilisearch 异步任务完成；退出成功与扫描数量都不等于文档全部生效或实际入索引数量。重复执行会按同一 ID 更新符合条件的文档，不清空索引、不删除历史残留文档，也不修改数据库帖子或搜索权限。任务中断后可在保持维护屏障的前提下排查并重跑，完成验收后再恢复写入。

## 验证边界

真实交互用例见 [`twitter-search.spec.ts`](../../../packages/frontend/test/e2e/twitter-search.spec.ts)：常驻入口与提交、普通及叠层出口冷／热切换、关键词与完整筛选更新、迟到结果隔离、解析失败不放宽、用户名与本地主机映射、权限独立、历史导航、窄屏键盘及默认 Misskey 界面。业务断言经过真实后端；延迟请求仅改变传输时序，不用伪造响应证明业务结果。

搜索展示回归同时检查 Twitter“选项”表单及其字段未挂载、分页工具条保留、日期定位与刷新保持当前关键词和路由筛选，以及自动请求不携带手动时间范围字段。默认 Misskey 作为对照，检查原生表单、时间范围和手动提交；中文及窄屏检查复用 [`twitter-localization.spec.ts`](../../../packages/frontend/test/e2e/twitter-localization.spec.ts) 的真实搜索数据。

话题快捷入口回归覆盖帖子与用户标签往返、用户标签直接链接及刷新：用户标签下入口和容器均未挂载，真实用户搜索仍接收完整 `#test`，用户简介中的标签保留，切回帖子后入口恢复。`@用户` 与 URL 快捷提示作为原有行为对照。

测试使用独立测试实例和合成数据，不能对共享开发或部署数据库执行重置。服务故障、索引维护与权限变化分别验证，不能以 Mock 或单张最终截图代替。截图 diff 固定测试数据、视口、DPR、主题、字体与缩放，切换过程还需确认页头 DOM 持续存在。具体 PASS 结果属于本次交付记录，不在现行契约中预先声明。

搜索页继续使用既有 Nitter 布局尺度和展示 Token，不将交互目标表述为未经测量的 X 实测结论。专项结果与截图不替代后置的 P-19 全站视觉基线；路由生命周期决策见 [ADR-0031](./adr/0031-search-route-lifecycle.md)，搜索控件取舍见 [ADR-0032](./adr/0032-search-options-presentation.md)。
