# Twitter 帖子详情、回复与初始化边界

## 当前范围

帖子详情继续由既有 `/notes/:noteId/:initialTab?` 路由和 `pages/note.vue` 查询原帖，`NoteDetailShell.vue` 呈现返回头，`NoteDetail.vue` 呈现正文、上下文、统计和各标签。不另建帖子实体缓存或第二套路由。

原有时间戳链接继续可用。时间线实体卡片、引用卡片和线程回复的正文／空白点击使用统一导航组合。纯转发外壳将导航交给实际显示原帖的内层卡片；嵌套引用和子回复由离事件目标最近的实体卡片处理。

本次不修改后端接口、基础分页器业务、基础表单的发布／上传／草稿规则，也不替换 Nitter 来源的布局 Token。

## 初始化依赖

`preferences.ts` 不再在模块求值时导入云备份实现。`cloudBackup()` 在实际执行时动态加载既有实现，自动备份的登录判断、开关、修改时间检查、周期以及成功时间更新保持原规则，DEV 调试入口复用同一包装。

`preferences/manager.ts` 在实际启用同步且未命中已启用快速返回时动态导入 `os`。剪贴板适配器同步发起 `navigator.clipboard.writeText()`，写入成功后才加载成功提示；写入失败和提示模块失败均被捕获，不显示虚假的成功提示。

`ui/twitter/context/index.ts` 是界面识别、布局及纯展示常量／类型的轻量公共入口。基础组件与页面使用这些能力时不能经由包含帖子组件的根 barrel。根 `ui/twitter/index.ts` 继续承载业务组件和业务能力；模块内实现使用叶子模块，`routing/index.ts` 不承担卡片导航业务。

这组边界消除偏好模块经 `os`、路由和帖子捕获模块回读未初始化 `prefer` 的静态环。浏览器普通模式与无痕模式的差异只能提示加载路径或持久状态不同；没有原异常调用栈和当时资源快照时，不能把具体触发因素确认为缓存或扩展。

## 卡片交互

普通正文点击复用既有路由和窗口注入策略。Ctrl／Command／中键保留新标签打开，Shift 遵循既有页面窗口行为。时间戳仍是实际链接，可由键盘和浏览器原生链接操作访问。

作者、头像、链接、按钮、媒体、投票、输入控件、内容折叠等交互不触发外层卡片跳转；已有文本选择也不会意外导航。显式 `data-twitter-note-interactive` 标记界定媒体和分页状态区域，判断不越过最近实体卡片。详情主帖本身不成为指向自身的点击卡片。

列表和详情卡片通过自身焦点边界调用原热键映射，保留 Enter／V 内容折叠与 R 回复等既有动作，避免祖先热键吞掉内部链接或按钮的 Enter。线程卡片的 Enter 入口同样仅处理根卡片自身获得焦点的事件。

返回继续使用现有浏览器历史与 Shell 滚动恢复。直接输入详情 URL、刷新和新标签均由已有详情路由承接；没有历史记录时不虚构来源页面。

## 内联回复

主帖下方的 `TwitterReplyComposer` 以原帖实体和频道上下文挂载 `MkPostForm`，不复制正文、附件、权限、创建请求或成功回执。

- 已登录：主帖回复按钮和 R 快捷键切到回复标签并聚焦同一编辑器。
- 未登录：显示既有登录／注册入口，原回复动作保留现有登录提示。
- 标签切换：编辑器使用 `v-show` 保持挂载，不因查看转发或反应而丢失未发送内容。
- 换帖：详情身份键将编辑器绑定到对应原帖，沿用原表单按回复目标区分草稿的规则；不同父帖草稿不串用。缓存路由保留的编辑器继续遵守既有输入生命周期，实际卸载时才执行销毁清理。
- 发送成功：原表单发布全局成功事件并清理自身已发送草稿；回复集合与计数分别从服务端重新确认。
- 发送失败：原表单的错误反馈及输入保留规则继续生效。

共享表单仅增加默认开启的回复上下文展示参数，以及对已有 `focus()` 的公开转发。详情已显示原帖，因此内联宿主隐藏重复原帖预览；其他表单保持默认展示。

## 回复查询与分页

`notes/replies` 是直接回复集合的唯一协议。引用帖归属既有转发／引用展示，不再因为 `notes/children` 同时返回引用而混入评论。

每个父帖持有一个 `TwitterRepliesPaginator`，唯一确认集合为继承的 `items`。根回复每页 30 条，子节点每页 10 条；请求多取一条判断是否还有结果，下一页从最后已显示 ID 继续，不以计数器猜测剩余页数。

两级都通过既有 `MkPagination` 展示首拉、错误、空态和“加载更多”，显式关闭下拉刷新和自动无限滚动。子线程仅在展开时取数，递归深度沿用现有限制；达到边界时保留“继续对话”链接。

同一父帖刷新时，适配器从最新回复逐页读取到原窗口最旧边界或查询结束，再一次替换确认集合。请求局部暂存不成为第二个业务缓存；失败保留原列表、游标和更多能力，并提供局部重试。

## 并发与生命周期

首拉、刷新和追加共用一个请求归属。重复更多点击不并发请求；显式重新加载遇到在途请求时合并一次刷新，返回的 Promise 覆盖该轮完成。

`useNoteReplies` 将成功发布和删除事件交给已有可见性刷新调度。隐藏标签／未展开节点保留意图，可见且空闲后处理。首拉开始前的意图由真实首拉覆盖；开始后的写入继续排队。

删除事件仅携带 ID。已显示成员删除需要复核；首拉、翻页或刷新在途时也需要复核，避免旧响应把尚未加入当前集合的已删除回复带回。最终卸载取消请求，迟到结果不能写回旧组件，也不会污染新父帖。

祖先链的 `notes/conversation` 请求同样归属当前详情实例，卸载时取消；重试不先清空已确认祖先。

## 验证入口

`twitter-note-detail.spec.ts` 使用隔离真实后端验证导航、交互豁免、回复归属、分页、内联发布、草稿隔离与在途请求。既有 `twitter-write-freshness.spec.ts` 区分内联表单和弹窗表单，避免把“发送后弹窗关闭”误套到常驻编辑器。

初始化问题需要同时检查正常启动和保留真实 HTML／服务端上下文、阻断自动 boot 后的独立模块加载。后者用于覆盖不同模块入口，不把正常启动一次成功视为环已消除。

结果与截图按当前验证批次保存；本文件描述契约，不将未执行的用例写成通过。历史选择见 [ADR-0019](./adr/0019-note-detail-initialization-and-replies.md)。
