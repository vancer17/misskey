# ADR-0030：帖子附件按内容比例展示与横向滚动

## 状态

已采纳（2026-10-25，项目所有者要求按讨论方案实施）。

范围为 Twitter 帖子卡片、详情主帖和线程行的附件展示。其他界面保留既有默认展示方式；敏感内容、权限、菜单、媒体播放与灯箱业务规则继续由原组件负责。

## 背景

此前多附件使用固定比例网格，图片和视频封面以 `contain` 缩放；附件比例与格子比例不同时，条纹或黑色背景会直接露出。增加附件数量还会产生多行布局。用户要求附件按自身尺寸适配，多附件保持一行并允许左右滑动。

Nitter `external/app/nitter/src/sass/tweet/media.scss` 提供 `379.5px` 高度上限、`533px` 宽度上限及约 `0.25em` 附件间距。其 `.attachments` 使用列方向，`.gallery-row` 隐藏溢出，部分图像采用 `cover`，不能据此声称 Nitter 已有本项目所需的滚动横条。

此前对 [X 四图帖子](https://x.com/NASA/status/2046969982131507400)的桌面页面探测观察到横向 flex、自动横向溢出、`4px` 间距、滚动吸附和导航按钮；图像采用 `cover`，存在裁切。该证据只覆盖所探测桌面样本，移动端尚未取得可复核的对应测量。

## 决策

1. 图片及视频附件按各自有效宽高比显示。高度上限采用 Nitter `379.5px`，继续受既有半视口上限约束，宽度不超过正文容器。附件框匹配内容比例，避免固定格子的填充带。
2. 单附件从正文起点放置；多附件单行、顶部对齐、`4px` 间距。较矮附件下方显示帖子表面，允许附件高度不同。极长截图和全景图保持完整，通过灯箱查看；不要求完整保留、同高且任意比例都限制宽度同时成立。
3. 横条采用原生滚动、邻近吸附、触摸板及触摸交互；溢出时提供前后导航。普通纵向滚动保持时间线语义，滑动不能误触导航或灯箱，减少动态效果偏好优先。
4. 保留一个完整的 `MkMediaList`，由 `TwitterNoteMedia` 提供展示参数并转发 `openGallery(id?)`。基础组件只增加默认保持原行为的展示能力；不拆分图库，不重写敏感、菜单、播放、揭示状态或灯箱规则。
5. 有效附件元数据优先；缺失时只消费现有加载链路的自然尺寸或视频元数据事件，作为可丢弃的 UI 几何。资源切换作废旧回调，不为敏感隐藏或省流附件额外加载资源。不修改后端接口或数据库，不持久化测量，不新增业务状态副本、架构开关或环境探测。
6. 完整保留截图内容是本项目在 X 横向交互参考上的明确适配，不能表述为复刻 X 裁切规则。主题表面承托透明内容，原文件自身黑边不自动去除。Nitter 附件外框为 `7px`；本项目继续使用原 Twitter 媒体外框的 `--twitter-radius-large`（`16px`），改由各附件承接，避免整个滚动轨道裁切按钮和焦点。

## 未采用的方案

- 只删除条纹或黑色背景：固定格子的比例仍与附件不一致，留下空区。
- 所有附件统一 `cover`：可能裁掉截图文字，与本次完整保留内容的选择冲突。
- 为每个附件创建独立图库：拆散整帖灯箱、敏感揭示映射及跨附件切换。
- 为获取尺寸创建隐藏资源：会扩大敏感或省流条件下的加载范围。
- 新增偏好开关切换旧网格与横条：本次是局部展示契约调整，无需引入新旧内部实现开关。

## 当前契约与验证

现行布局及所有权见 [帖子附件布局](../media-attachments.md)，来源映射见 [保真审计 E-3](../port-fidelity-audit.md)。真实后端上传、发帖、浏览及播放链路验证业务行为；几何与截图 diff 分别检查比例、滚动和背景。

本 ADR 不预先声明测试或平台验证通过。桌面 X 样本不能替代移动端验证，专项截图不自动成为 P-19 正式视觉基线。
