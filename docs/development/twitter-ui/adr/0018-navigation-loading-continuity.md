# ADR-0018：主路径加载连续性与局部保留刷新

## 状态

已采纳（2026-10-22，项目所有者要求按讨论方案实施）。

## 背景

人工走查发现，新注册用户从频道入口进入具体频道时，中间栏出现闪动。代码核查与浏览器分段观测确认：路由的立即 Suspense fallback 使用原主题背景；频道还需加载内部展示模块，并在 `channels/show` 等待期间只呈现标题和空正文，随后再挂载帖子查询。

个人资料存在相同代码等待，同时原 profile 骨架缺少返回头，横幅及头像尺寸与实际内容不同。时间线已经静态加载；通知已有页头和骨架，两者不能一概归因为路由懒加载。原分页器的 `reload()` 会清空条目，局部预加载不能解决同查询刷新期间的内容撤下。

用户提供的 `tmp/community_for_x` 静态归档能确认 X 使用拆包、加载边界和查询缓存，但不能证明频道 hover 预取、导航时序或加载阈值。本项目借鉴职责与反馈方式，布局尺度继续依据 Nitter 和既有 Token。

## 决策

1. 为既有路由出口增加可选展示插槽和背景变量，并沿出口子树继承。不复制路由器，不改变路由键、缓存和导航提交语义。
2. Twitter 业务出口统一代码加载占位，页面自身分别负责实体及列表加载。频道补齐状态，个人资料保持同一返回头并对齐骨架尺度；时间线和通知复用已有完整状态。
3. Twitter 分页状态直接交接，保留默认 UI 原过渡和流式行级动画。基础分页业务逻辑不为本次视觉问题而重写。
4. 频道实体和热门集合分别只有一个局部查询所有者；个人资料复用原分页能力，由具体查询所有者实现保留结果刷新。请求临时结果不是第二份业务状态；只有成功确认后才替换已加载窗口。
5. 时间线与通知保持原流式、队列、未读及手动刷新语义，不新增通用流式框架，也不停止刷新来获得视觉稳定。
6. 代码预加载由真实入口意图触发，与正式路径复用动态 loader。只加载代码，不预取 API、不缓存实体、不依赖 Vue 私有字段或新增路由表。
7. 使用现有真实后端测试设施逐阶段验证；正式视觉基线继续遵守阶段出口条件。

## 未采纳方案

- 只增加预加载：无法覆盖弱网、冷缓存、失败及 API 空正文。
- 调大 Suspense timeout 或等待全部 API 再导航：引入旧画面与新 URL、滚动恢复之间的额外协调，仍未补齐页面加载态。
- 全局修改原分页器 `reload()`：扩大已有基础逻辑的影响范围。
- 复制条目、双分页器或 DOM 快照：引入状态副本，无法保持真实分页、删除和写后新鲜度。
- 全量登录预热及通用查询／流式框架：超出本次局部缺陷的实际需求。

见 [主路径加载与刷新](../navigation-loading.md)。本 ADR 不记录尚未执行的验证为通过。
