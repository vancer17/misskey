# ADR-0033：接入独立私信工作区及账户未读同步

## 状态

已采纳（2026-10-25，项目所有者要求按讨论方案实施）。

## 背景

第一阶段将 Chat 放在 Hide 范围，Twitter 导航没有入口，个人主页仅通过原生更多菜单提供联系动作。原生聊天已有本地私信和群聊后端，但移动页面发送区域与 Twitter 发帖悬浮按钮重叠。仅增加按钮无法解决会话索引、权限提示、阅读副作用和独立工作区滚动问题。

所有者提供 X 用户主页和 Chat 工作区参考图及本地采集资源。Nitter 继续承担可覆盖部分的空间参数；其没有聊天工作区，因此此处采用 X 采集代码中可证实的分栏、页头和空态尺度。参考表现不代表引入 X 的加密协议或其他后端能力。

## 决策

1. 将 Chat 纳入 Twitter 页面范围，复用现有 `/chat` 系列路由。路由入口按既有 UI 上下文只挂载一个页面；真实存量原生 UI 是保留原页面分支的消费者，停止支持该 UI 后才可移除此分支。
2. 独立工作区由路由名称确定展示布局，退出普通流式页面的滚动契约。桌面移除推荐栏并使用图标侧栏，移动会话隐藏底栏，所有私信页隐藏发帖 FAB。收件箱和消息列表持有局部滚动，普通内容页仍由 Shell 恢复位置。
3. ChatService 持有联系权限、会话聚合和显式标读权威事实；不在主页、组件和路由守卫重写接收范围或拉黑规则。接口先完成会话级聚合再分页，避免一个高频会话挤掉其他会话。
4. 新页面历史查询显式关闭读取即标读；可见底部观察通过真实消息 ID 标读。Redis 原子操作维护并发未读标记，账户级失效事件驱动权威账户快照对账。原生调用省略新参数时维持既有默认行为。
5. 独立账户内存 Store 沿用 Misskey 的 Vue 状态基础，不新增 Pinia 运行依赖或持久化消息正文。所有业务写入通过 Action，组件只保留表单和几何状态。外部只消费模块索引，不直接引入内部实现。
6. 结果不确定的发送保留草稿并要求用户先核对历史；不做自动重发，也不添加未经服务端实现的幂等承诺。反应、删除、附件和群管理接入真实已有 API；需要的协议增量同步生成 misskey-js。
7. 仅提供后端支持的完整本地聊天能力。远程聊天、加密、通话、输入提示和对方已读没有服务端支持，不通过 feature flag 或假状态引入。

## 未采用的方案

- 只开放原生 Chat 并补一个入口：仍存在移动遮挡和原生页面外观，且读取即标读不满足新工作区的观察契约。
- 从有限消息列表计算会话和全局未读：消息分页不是会话分页，无法证明未装载会话是否未读。
- 前端依据关注字段直接决定发送权限：复制并延迟了服务端接收范围、拉黑与角色规则。
- 用运行配置切换新旧聊天内部架构：既有 UI 选择只控制展示，业务协议应通过请求 Schema 演进。
- 复用共享测试配置覆盖开发运行配置：开发 watcher 会重新读取该文件，可能转向测试端口。真实集成测试使用独立运行根目录和独立数据库。

## 结果与验证边界

新工作区复用已有聊天存储和流式通道，新增的接口增量服务于明确的数据所有权与分页／标读行为，不需要数据库迁移。实现契约见 [messages.md](../messages.md)；实际测试与视觉结果以交付记录为准。专项浏览器验证不替代后置 P-19 全站视觉验收，也不替代移动真机输入法、软键盘和 Safari 核查。
