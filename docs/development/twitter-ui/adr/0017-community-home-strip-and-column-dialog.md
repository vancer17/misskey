# ADR-0017：首页专属频道横条与管理窗口主列居中

- 状态：已实施
- 日期：2026-10-21
- 范围：Twitter UI 的 `/channels` 入口及“我的频道”窗口
- 替代：ADR-0015 中发现页推荐频道横条的选择；资料库桌面定位由本决策明确

## 背景

ADR-0015 曾把 Misskey 的推荐频道映射为发现页的频道横条。X 归档的 Home 使用成员社区卡片，Explore 使用主题入口；把两页都渲染为频道卡片与用户明确的首页专属横条目标不符。

原管理窗口使用全局视口居中。Twitter 三栏左右宽度不同，频道主列并不处于视口中线。1440px 隔离浏览器实测中，窗口中心为 720px，主列中心为 677.5px，两者相差 42.5px。用户明确要求“我的频道”相对频道主列居中。

## 决策

1. 首页保留 `channels/followed` 横条与 `channels/followed-timeline`。发现只显示 `channels/global-timeline`，移除 Twitter 分支的推荐横条消费者、props、重试及刷新调度。默认 Misskey 推荐标签仍使用既有端点。
2. 关注、所属、收藏与参与人数维持原有独立语义，不增加自动关注、数据迁移或旧数据兼容推导。已有和新增关注经同一端点读取，回访与整页重进仍由真实服务端关系决定。
3. 桌面“我的频道”的水平目标来自频道页面实际 DOM 中心；纵向保留可用视口居中。收藏和其他基础窗口没有收到目标参数时仍按视口居中，手机保留抽屉。
4. 新增 UI 定位组合函数，在窗口期间观察主列及祖先布局变化。初次同步测量，后续按帧合并；关闭、停用及卸载清理。几何不进入业务域或业务状态。
5. 基础窗口仅增加 `dialogCenterX?: number` 原始布局参数。模态层调整水平留白与缩放原点，保留全屏遮罩、背景隔离、焦点及关闭机制；空间不足时窗口由原排版约束自动收窄。

## 验证与后果

真实后端 E2E 检查首页已有及新增关注、刷新重进、发现无横条和无推荐请求；独立检查所属频道不会被自动补作关注。浏览器几何以主列实际中心为期望，桌面中心误差不超过 1px，覆盖右栏消失、打开期间 resize、同宽过渡、加载／失败／长短内容与移动抽屉。
