# ADR-0011：头像挂件页的布局、试戴与确认写入

## 状态

已采纳，2026-10-19。

## 背景

Nitter 不包含头像挂件配置业务。旧设置页在空目录时只显示头像和佩戴数量，目录请求失败没有重试；试戴弹窗派发事件后立即关闭，页面还使用提交数组代替服务端回执回填账户。

## 决策

1. 保留 Misskey 的路由、目录 API、账号策略及账户单例。新增的头像挂件能力不自建 Store，不修改基础 `MkAvatar`、`MkModalWindow`、`MkButton` 的内部业务逻辑。
2. 页面采用当前头像、已佩戴条目、可选目录三段式布局。颜色、排版、区块内距和主列宽度消费 ADR-0001 的 Nitter 来源 Token；响应式使用现有 `useTwitterLayout`。挂件专属 72px 主头像、60px 卡片头像、64px 编辑头像、140px 最小卡宽沿用改造前组件的实际值，不宣称来自 Twitter 实测。
3. 挂件编辑是明确的 Misskey 扩展。弹窗采用 440×620 的布局容器，媒体越界留白按基础头像组件 200% 挂件图层及允许变换范围预留；这部分作为项目自定义呈现验收，而非与不存在的 Nitter 挂件页逐像素对齐。
4. 目录数据只控制目录加载、空态与错误态，不决定是否显示已确认的佩戴记录。保留成功目录应对刷新失败，回访重新加载，取消旧读请求并防止迟到响应覆盖。
5. 试戴仅持有临时变换草稿。页面提供可等待的保存命令；保存期间禁止重复提交和弹窗关闭，失败保留输入，成功后才关闭。路由离开不把已发出的写入当作已取消；回执仍需校验账户身份。
6. 保存复用 `i/update`，只将其确认的 `avatarDecorations` 字段通过 `updateCurrentAccountPartial` 回填账户。后端过滤或归一化导致结果不同时，显示已同步实际结果的说明，不提示虚假的佩戴成功。
7. 旋转和位移使用业务弹窗内原生范围控件，提供标签、数值和键盘操作。不为该功能重构基础范围组件。仍使用原协议单位与步长。
8. 真实后端验证账号权限、数量限制、重复挂件顺序、失败及迟到回执。单元测试只证明请求映射。截图与尺寸证据用于检查实现；未经批准的目标截图不自动升级为正确基线。

## 后果与边界

- 实例无素材时显示中文空态；不自动配置假挂件。管理入口沿用 `/avatar-decorations` 及既有管理员／角色策略。
- 佩戴上限下降仍遵守后端数组长度校验，保留全部移除入口，不扩大兼容路径。
- 本页的忙碌状态和佩戴快照校验不构成分布式锁；未新增跨标签页 CAS 或后端协议。
- 中文资源按本次明确要求同步提供，现有禁止手改非日文资源的检查会报告该已知例外；不修改检查器以掩盖例外。
