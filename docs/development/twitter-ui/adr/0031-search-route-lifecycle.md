# ADR-0031：搜索路由身份、查询生命周期与能力运维分离

## 状态

已采纳（2026-10-25，项目所有者要求按讨论方案实施）。

范围为现有搜索页、Twitter 常驻搜索入口、搜索结果生命周期与搜索维护命令。布局继续依赖现有 Nitter 参数；本 ADR 不声明新增 X 实测数据或正式视觉基线。

## 背景

人工核查发现，常驻搜索回车后帖子区显示“帖子检索不可用”；帖子与用户标签往返有时需要点击两次，切换还会撤下中间栏内容。排查确认这些现象由不同链路产生，不能用一次界面样式调整共同解释。

帖子搜索提示来自前端角色策略门控，用户搜索使用独立能力。此前模块加载时保存的普通布尔值不会随账户或实例资料继续更新。所检查部署还选择了 Meilisearch，但服务未响应；即使开放角色权限，仍需恢复引擎并核对历史索引。公开实例策略与登录账户的有效策略并不等价。

标签此前先更新局部 `ref`，再执行路由替换。普通出口以完整 URL 为默认缓存键，离开时缓存的实例已经保存目标标签；再次激活旧 URL 时，路由 props 未变，同步 watcher 不执行，局部标签因而与地址相反。第二次点击才更正局部值。完整 URL 改变还会替换或激活整页，异步结果模块使外层立即 Suspense fallback 接管主内容，形成页头消失的闪变。

常驻搜索框读取路由定义中的 `q: 'query'`，把字段映射误当关键词，显示了字面量 `query`。可选筛选在构造 URL 时带入 `undefined`，序列化后成为非空字符串，后续被视为真实用户或主机条件。帖子结果页还依赖 setup 时的一次性用户解析；直接固定页面身份会使后续用户与主机筛选保持旧值，因此不能只改缓存键。

## 决策

1. **路由是已提交搜索条件的来源。** Twitter 标签从 `props.type` 只读派生，点击只提交导航，不先写局部标签。关键词草稿是临时 UI 状态；常驻入口使用当前解析后的路由 props。序列化仅包含有效简单字段，不输出字面量 `undefined` 或 `null`，不把实体放入 URL。
2. **稳定当前搜索页的展示身份。** `/search` 使用现有 `viewKey` 契约，普通出口不增加另一套缓存。实验叠层由 Twitter 宿主指定 `stableViewPath="/search"`，仅原位更新当前同路径卡片，保留展示键；新卡片与历史卡片保持独立，其他页面继续原有叠层行为。共享组件只增加展示身份能力，不理解搜索业务。
3. **加载边界落在结果区。** 搜索框、标签与来源栏保持挂载，搜索模块等待由内层 Suspense 处理，真实查询状态由结果组件与原分页组件呈现。默认 Misskey 页面同步完整新路由条件、清除旧手动结果并保留手动提交，不以重写基础搜索逻辑换取视觉稳定。不同叠层实例使用独立 ARIA 标识，焦点限定当前标签栏；新导航同时撤销旧 URL 查找的导航资格。
4. **完整筛选先确认再查询。** 帖子结果将关键词、用户标识、用户名、主机整体更新；用户解析可取消，旧解析无提交资格。标识优先，不在失败后换用另一个身份。解析失败或范围不允许时阻断查询，不自动扩大范围。相同主机规范化结果按各接口约定映射：`users/show` 本地省略主机，`notes/search` 本地使用 `.`。用户搜索同步提交关键词和来源，避免中间组合。
5. **原分页器继续唯一持有结果。** 完整条件改变时替换分页器，列表挂载负责初次加载；旧请求只更新旧所有者。不增加条目副本、双分页器或新的查询 Store，不为视觉连续性复制业务事实。
6. **权限与运维分别处理。** 前端能力从既有账户／实例策略经 `computed` 单向派生，后端仍最终授权。服务连接与提供方属于后端部署配置；引擎故障不自动改角色、不切换领域规则，也不进入业务组件、Store 或 domain 的运维探测。现有 `sqlLike` 只作为显式部署选择，配置变更需要编译并正常重启后端。
7. **提供有界、幂等的维护回填。** `backfill-note-search` 在固定最大帖子 ID 内以 100 条 ID 游标批次扫描，复用 `SearchService.indexNote()` 的资格与映射。仅提交现存符合条件的文档，不清索引、不修改帖子、不声明异步索引已成功。执行前暂停全部帖子写入并等待在途写入结束；提交完成后继续暂停，直到本轮 Meilisearch 任务全部成功且真实搜索验收完成。

## 未采用的方案

- 只让本地标签更早响应或延迟路由提交：保留两份已提交状态，缓存回访仍可能分歧。
- 全局停用 KeepAlive、清缓存或手动绕过路由修改浏览器历史：扩大路由行为影响范围，掩盖错误的状态所有权。
- 仅添加固定 `viewKey`：叠层出口原来不消费该能力，结果页的一次性用户解析也仍会留下旧筛选。
- 让叠层所有搜索卡片共用一个键：不同历史卡片可能复用同一实例，破坏叠层历史与展示身份。
- 调大外层 Suspense 等待时间或仅预加载模块：不能保证冷缓存及慢请求时页头连续，也无法修复双击与筛选生命周期。
- 用户解析失败后删除用户条件继续搜索：把错误变成更宽范围的结果，可能产生看似成功但事实错误的命中。
- 前端探测 Meilisearch、硬编码允许搜索、引擎故障自动回退 SQL：跨越权限与部署边界，使运行规则取决于组件探测结果。
- 回填另写一套索引规则、全表载入内存或清空重建索引：复制权威规则、失去有界扫描或引入额外数据破坏。
- 在持续写入下仅依靠固定上界回填：ID 上界不能阻止既有帖子编辑／删除与迟到索引提交相互覆盖，不能替代维护屏障。

## 结果与验证边界

搜索页容器、路由参数、异步用户解析及分页结果形成单向数据链。共享出口新增能力只控制当前卡片展示身份；权限来自现有策略，服务运维留在部署与维护入口。维护命令有界且可重跑，但不提供事务快照、写入屏障、异步任务完成保证或历史残留文档清理。

现行契约、维护命令与操作条件见 [Twitter UI 搜索](../search.md)。真实后端交互见 [`twitter-search.spec.ts`](../../../../packages/frontend/test/e2e/twitter-search.spec.ts)，索引回填与提供方行为使用相应真实后端／引擎验证。测试结果以交付记录为准，不在 ADR 中预先记为通过。专项截图与连续性断言不替代后置的 P-19 全站视觉基线。
