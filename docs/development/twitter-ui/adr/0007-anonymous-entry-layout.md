# ADR-0007：匿名入口与业务 Shell 分离

状态：已采纳。日期：2026-10-16。

当前实现见 [anonymous-entry.md](../anonymous-entry.md)。

## 背景

会话恢复修复后，失效缓存可以回到匿名状态，但 `?ui=twitter` 仍选中三栏外壳，根路由又按未登录身份选择原版欢迎页。结果是业务导航、发帖入口和右栏包裹包含统计、访客时间线及阴影卡片的完整 Misskey 欢迎页。此前会话测试验证了启动成功，却没有验证匿名布局排除项。

第一阶段 P-00 只要求已登录 Shell，匿名首页原为阶段外。现在将匿名入口及相关组合边界纳入第二阶段 P-26。

## 决策

Twitter 根组件保持唯一的路由、风格与全局弹层宿主；在首帧前根据既有账户和路由派生入口／内容布局。入口不挂载业务 Shell；匿名公开内容仍可访问，但不显示登录专属导航、推荐与发帖组件。实例初始化独立保留且优先于普通欢迎页。

登录／注册只复用原认证流程的入口，不复用整个 `MkVisitorDashboard`，也不复制密码、Passkey、规则确认、邀请码或 token 持久化实现。UI 参数不参与鉴权。

Nitter 的登录路径没有实际实现，因此指定 X 归档仅作为匿名入口的补充布局来源。入口尺度经新增语义 Token 与入口专用权威断点消费，不改变现有业务 Shell 的参数。

## 明确适配

X 品牌替换为实例品牌，默认使用现有高分辨率 Mi 图标；字体沿用本项目，不分发归档中的字体。标题、操作与页脚使用已有 i18n 和真实实例能力。归档中的第三方登录和手机号能力没有移植。

紧凑视口仍保留注册入口，以提供 Misskey 实际注册能力；不因归档窄屏只显示登录而隐藏注册。因为未接入 X 的多项认证入口，不保留其 440px 最小操作区空槽；整体两列／单列关系、面板上限、按钮高度与间距仍可追溯到归档。现行文档列出参数映射及验证边界。

不通过全局 CSS 隐藏业务组件，也不强制所有匿名公开路由跳转首页。不重新设计登录协议，不引入第二套 Store，不增加新旧架构切换开关，不回退已落地的会话恢复。

## 验收与限制

增加结构排除、网络副作用排除与真实后端登录／注册／失效恢复回归，保持旧会话测试。局部截图输出为待审阅候选，不能自动充当正确的设计基线；P-19 的正式基线仍需确认。取证重放仅加载本地资源且禁用原站脚本，不把归档程序接入产品运行时。
