# ADR-0020：发帖编辑器焦点、策略区与工具栏空间分配

## 状态

已采纳（2026-10-22，项目所有者要求按讨论方案实施）。

本决策替代 [ADR-0001](./0001-design-token-source.md) 中发帖正文编辑区补充的底部焦点线方案；正文排版、原生控件映射、频道信息行与计数的其余决策继续适用。

## 背景

人工走查发现，Twitter 发帖弹窗的正文获得焦点时出现蓝色底线，CW 和独立话题输入获得焦点时出现蓝色矩形。正文底线来自编辑区外层的 `::after` 与 `:focus-within`，辅助输入矩形来自共享的品牌色 `:focus-visible`。文本输入控件经鼠标点击也可能匹配 `:focus-visible`，因此该规则没有形成预期中的键盘专属反馈。

可见性与联邦按钮原来位于底部右侧的不可收缩动作组，左侧工具栏可收缩并允许横向滚动。可见性文案变长会压缩左侧空间，导致“仅关注者”首先触发原生横向滚动条；“指定用户”隐藏联邦按钮，故同为四字文案却不一定溢出。窄容器及额外 MFM／插件按钮也会触发同一问题。“指定用户”的收件人内容进入正常文档流，本身应当增加编辑器高度。

触屏窄视口的补充检查还发现，390×480px 下长正文、投票和指定收件人叠加后，原抽屉宿主会裁掉顶部关闭入口。即使底部仍能发布，也不能把关闭入口不可达视为可接受的自然增高。

Nitter 没有发帖编辑器，相关结构以本地 X 采集 `tmp/community_for_x/abs.twimg.com/responsive-web/client-web/` 补充：

- `sharedbundle.Composebundle.RichTextCompose.59865fed1a244af7a.js` 的 `_renderAudienceControls` 位于正文输入之前；`_renderControlsAndToolbar` 分别呈现策略控制与工具栏；`_renderToolbar` 使用独立的可横向浏览工具容器。正文的 `_fieldTextInputProps` 使用 `selection` 输入样式，`textInputStyle` 的横向 padding 为 0。
- 同一 Compose 文件的 `_isVeryNarrow` 在容器宽度小于主题 `xxSmall` 时使用 `toolBarVeryNarrow`，该样式将工具栏改为纵向；`main.3df9dbfbc9c6567ba.js` 的主题将 `xxSmall` 定义为 320。
- `sharedbundle.UserProfileondemand.HoverCard.20d0a3eecc79221ca.js` 中的共享模块 `251051` 定义了 Compose 消费的横向浏览容器：内容使用 `overflowX: auto` 与 `scrollbarWidth: none`，前后导航按钮绝对定位；方向键导航排除输入控件和可编辑内容，并按 reduced motion 选择滚动行为。
- 同一 HoverCard 文件中的共享弹层样式将 `dynamic` 模式的最大高度设为 `90vh`。本项目以该上限作为来源，并映射为 `90dvh` 适应动态视口；这是共享样式来源及项目映射，不等同于完整 Compose 弹窗的高度实测。

这些是归档源码的结构与样式事实。采集缺少打开状态的完整 Compose DOM，`bundle.Compose.53d4a59d8cb8408da.js` 还是 `No Content` 占位，不能据此声称整张弹窗已与 X 像素一致。X 的受众与回复权限也不等于 Misskey 的可见性；CW、独立话题、指定收件人及联邦开关的摆放属于本项目适配。

## 决策

1. Twitter 变体的正文、CW 与独立话题输入统一使用无品牌色焦点边框的编辑表面，删除正文焦点伪底线。保留插入光标、选区、输入可访问名称与 Tab 顺序；按钮、菜单等操作控件继续提供键盘焦点反馈。规则仅限本表单的 Twitter 展示变体。
2. 将原有可见性与“仅本地”控件移入正文列顶部的独立策略行，保留原事件、锚点和业务条件。策略行允许换行；指定收件人位于其下并按内容自然增高。可见性文案及联邦按钮显隐不再参与底栏空间分配。
3. 底栏左侧承载原有全部工具，右侧保留“更多／发帖”。左侧可以收缩，右侧保持可用；空间不足时隐藏原生滚动条，并通过前后导航、触摸滑动及聚焦自动滚入提供工具访问。保留每个原按钮及其真实事件锚点，不为此重写工具的业务入口。
4. 方向键处理限定在工具栏内部，正文光标不受影响；导航按钮不消耗内容的可用宽度，并为焦点环与两端控件保留空间。滚动遵循现有动效偏好及 reduced motion。
5. 使用 `ResizeObserver` 从表单及工具容器的实际尺寸派生紧凑布局和溢出导航状态，卸载时清理。测量只产生组件临时 UI 状态，不进入 Store、领域事实或环境探测。小于 320px 的容器采用纵向底栏，阈值由 `domain/layout.ts` 单点定义。
6. 发布、上传、草稿、频道、可见性权限、收件人以及 `localOnly` 继续由原表单业务所有者负责。展示重排不创建第二套业务模型或状态，也不修改默认 Misskey UI 的布局与发布规则。
7. 在 `MkPostFormDialog` 的 Twitter 表单宿主消费 `--twitter-composer-dialog-max-height: 90dvh`，通过 `max-block-size` 限制最大高度，横向隐藏溢出、纵向自动滚动并设置 `overscroll-behavior-y: contain`。内容仍自然增高，超限后关闭与发布入口均通过宿主滚动触达；沿用原有关闭和发布生命周期，不修改全局 `MkModal`。

## 未采纳方案

- 仅隐藏原生滚动条：没有修复可见性挤压，也未补齐被遮挡工具的访问方式。
- 固定可见性按钮宽度：仍占据底栏有限空间，窄容器与额外工具仍会溢出。
- 用品牌色底线替代正文轮廓：缺乏目标设计依据，且与辅助输入形成不一致的编辑表面。
- 将原工具统一迁入“更多”：扩大工具事件及弹层锚点的改造范围，缺乏本次缺陷所需的理由。
- 在全局监听方向键或增加设备探测：工具导航属于局部 UI 交互，不能影响正文编辑或引入业务层环境职责。

## 当前契约与验证边界

当前展示契约见 [帖子详情、回复与初始化边界](../note-detail.md)。定向验证应覆盖正文／CW／话题焦点、四种可见性下的底栏几何、指定收件人的自然增高、工具溢出访问及 319／320／321px 边界，并保留默认 UI 对照。前后导航按钮在滚动边界隐藏前，须把自身焦点交接给首个／末个可用原始工具，避免焦点回落到 `body`；LTR、RTL 及交接后的 Tab 续行均需核对。

移动抽屉还需在 390×480px 等矮视口中组合长正文、投票和指定收件人，以触屏手势分别滚动至顶部关闭与底部发布，确认两者均可见、可操作，关闭及发布后仍沿原生命周期完成。

隔离布局与 Mock 只能证明展示、事件接线或协议映射；发布权限、收件人、频道、`localOnly` 和草稿恢复的业务行为需要真实后端集成验证。具体通过、失败及未执行项由当前验证记录报告，本 ADR 不替代执行证据，也不提前固化完整视觉回归基线。
