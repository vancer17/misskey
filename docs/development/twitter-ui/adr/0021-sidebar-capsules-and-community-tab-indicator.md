# ADR-0021：侧栏视觉胶囊与频道标签指示条

## 状态

已采纳（2026-10-22，项目所有者要求按讨论方案实施）。

范围为 Twitter UI 的 `Sidebar.vue` 与 `/channels` 的首页／发现标签；不重新裁决全站 Shell 列宽，也不修改 Misskey 基础导航组件。

## 背景

人工核查发现，左侧导航的选中胶囊及发帖按钮靠近主列边框。完整侧栏宽 `275px`，根内距左右各 `8px`；纵向 Flex 容器默认拉伸子元素，使整行链接的背景和发帖按钮都占满 `259px` 内宽，视觉边缘距主列仅 `8px`。这是侧栏内部视觉元素与整行点击区域重合所致；在 Shell 栅格增加列间距会移动主列及依赖主列坐标的窗口，扩大修复范围。

频道首页／发现的指示条使用固定 `56px`，而现有 `TimelineHeader`、`TwitterSearch` 采用按钮两侧固定内缩，导致同一 Twitter UI 下的标签宽度规则不一致。截图中的物理像素还受浏览器缩放与 DPR 影响，不能把截图宽度直接当作 CSS 尺度。

同一标签交互的验收还发现，原键盘处理在写入 `defineModel` 后立即读取 `tab.value` 定位按钮。模型 setter 向页面所有者发出更新时，新的 prop 尚未同步回传，getter 可能仍返回旧值，导致 ArrowRight 已选中发现却将焦点留在首页；Home／End 也存在同一时序问题。

## 来源证据

Nitter 的 `external/app/nitter/src/sass/navbar.scss` 提供顶部横向导航，没有同构的左侧纵向主导航或发帖入口。侧栏局部结构采用本地 X 归档补充，文件均位于 `tmp/community_for_x/abs.twimg.com/responsive-web/client-web/`：

- `loader.SideNav.abc2a60017aefc0ea.js` 模块 `634040`：`rootPaddingNormal` 使用横向 `space8`；`topSection` 沿起点对齐；发帖 `button` 的宽度是 `90%`。这不支持把侧栏根内距任意扩大为 `24px`。
- `sharedbundle.Composebundle.ComposeGrokMediabundle.ComposeMediabundle.Delegatebundle.Grokbundle.Payments.517af20de8a4bcaaa.js` 模块 `829598`：导航外层 `vertical` 使用 `width: 100%` 与起点对齐，内部视觉层 `base` 使用无限圆角和 `maxWidth: 100%`，内部 `vertical` 承载图标、文字和内距。整行命中区与视觉胶囊分别布局。
- `sharedbundle.Communitiesbundle.UserLists.9bb579fc32d96cb9a.js` 模块 `262461`：指示条 `border` 使用 `width: 100%`、`minWidth: "56px"`，位于内容容器中。X 的原规则是内容宽度加最小值，并不是固定 `56px`，也不是随半列伸展的长指示条。

Nitter `external/app/nitter/src/sass/timeline.scss` 的 `.tab-item` 使用 `flex: 1 1 0`，其块级链接以底边框呈现选中状态，横向随等分单元伸展。项目以 Nitter 为适用布局的地面真值；本次据此保留等分单元的空间关系，并统一到当前时间线／搜索的双侧内缩表现，不采用 X 内容型指示条。

归档脚本是结构与默认样式的证据，不包含本次目标状态的完整运行时测量；因此不能据此声称侧栏或频道页已与 X 像素一致。

## 决策

1. 保留既有完整侧栏 `275px`、图标侧栏 `72px`、主列最大 `600px`、右栏 `350px` 及布局断点，侧栏根内距继续使用 `8px`。不增加 Shell 列间距，也不引入 DOM 测量或布局状态。
2. 每个导航链接保留整行点击区域，增加按内容布局的内部视觉胶囊。将背景、圆角、图标文字间距、内距及悬停／选中／键盘焦点反馈归到该胶囊；胶囊最大宽度受链接约束，长文案允许省略，链接保留完整可访问名称。原事件、路由、预加载和未读事实继续由现有实现负责。
3. 完整侧栏的发帖按钮占内宽 `90%` 并沿逻辑起点对齐。在无局部滚动条占位的 `275px` 侧栏中，按钮宽约 `233.1px`，至主列边框约 `33.9px`。图标模式继续使用居中的 `52px` 控件。
4. 频道首页／发现仍为两个等分按钮。移除指示条固定 `width: 56px`，设置逻辑起止内缩均为 `--twitter-space-3`（默认 `12px`），由定位约束派生宽度。保留 `4px` 高度、原颜色和圆角，符合现行 `TimelineHeader`／`TwitterSearch` 的几何规则；其余页面与 Misskey 基础 tabs 不在本次修改范围。
5. 标签的点击区域、ARIA 关联、原搜索恢复逻辑和所有查询所有权保持现有实现。方向键及 Home／End 的处理先从既有标签定义计算带权威类型的局部目标 `nextTab`，再将同一值写入模型并用于焦点选择器，避免同步重读尚未回传的模型。局部目标只服务本次事件，不构成持久状态或业务事实副本。

## 未采纳方案

- 增加全局栅格间距或修改侧栏列宽：会移动主列及按主列居中的窗口，且未处理整行背景拉伸的直接原因。
- 把所有导航链接本身缩成内容宽度：缩小现有命中区域；内外层分离可以保留整行操作能力。
- 把固定 `56px` 换成另一个固定长度：无法形成适应主列宽度的统一规则，也不是对 X 原始内容型规则的准确迁移。
- 将其他页面全部改成 X 内容型指示条：背离本次已批准的 Nitter 空间优先及现有页面一致性目标，扩大实现范围。
- 新建共享业务 tabs 组件或运行时测量指示条：当前两个局部样式修复不需要额外的抽象、状态或生命周期。

## 验证与当前契约

当前契约分别见 [主滚动布局](../scroll-layout.md) 与 [频道入口布局与请求边界](../communities-layout.md)，来源映射登记在 [保真审计](../port-fidelity-audit.md)。

验证需覆盖 `1280px`／`500px` 断点两侧、完整侧栏与图标侧栏、长文案、未读徽标、悬停和键盘焦点；测量整行链接与内容胶囊，并核对主列边框没有水平迁移。频道页需核对指示条实际宽度等于按钮宽度减 `24px`，覆盖首页／发现切换、方向键、Home／End、搜索关闭恢复及原请求次数。每次键盘切换需同时断言选中值、ARIA 与实际聚焦按钮一致，而非只检查内容面板已切换。

截图与 diff 固定视口、DPR、缩放、字体、主题和数据。布局采样只证明表现与命中边界，业务交互仍使用真实后端验证；实际通过、失败和未执行项随本次交付报告记录，不在本 ADR 预先声称测试通过，也不自动建立 P-19 正式视觉基线。
