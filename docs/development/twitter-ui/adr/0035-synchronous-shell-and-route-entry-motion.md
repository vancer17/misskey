# ADR-0035：同步 Shell 布局与路由内容轻淡入

## 状态

已采纳（2026-10-25，项目所有者同意实施导航布局稳定与路由内容轻淡入）。实现及本轮验证已完成；分组运行结果、视觉材料与未核验边界见 [route-entry-motion.md](../route-entry-motion.md)。

本决策补充 [ADR-0034](./0034-messages-shared-shell.md) 的共享导航与列宽约定，替代由异步页面 `needWideArea` 元信息决定 Twitter Shell 几何、按页面变化反复卸载右栏的做法。ADR-0033 和 ADR-0034 原文保留；私信业务、路由、独立滚动、权限、草稿与标读契约继续有效。

## 背景

私信工作区与普通内容页共享导航尺度后，离开私信进入尚未加载的普通页面时，Shell 仍可能消费上一页的 `needWideArea`。旧值使右栏暂时缺席，普通页按另一组栅格绘制；新页面注册元信息后，右栏和列宽才改变。在真实延迟页面模块的观测中，1440px 视口从私信进入通知页，加载阶段为 `72px + 600px`，完成后变成 `275px + 600px + 350px`。淡入只能调整绘制，不能解决这种几何来源变化。

右栏承载搜索、趋势和推荐关注。将其存在性绑定到路由异步元信息，会在往返私信时重建既有卡片实例和查询。路由内容的出现也缺少统一的轻量交接；为此重建整个路由出口、复制离场页面或延迟业务请求会扩大生命周期和状态所有权，超出展示修复范围。

## 决策

1. Twitter Shell 的布局分类由同步解析的当前路由派生，权威定义放在 `ui/twitter/domain/layout.ts`，经轻量公开入口提供。主列、侧栏、右栏与私信工作区均消费同一份分类；页面元信息继续服务标题等展示，不反向决定 Shell 几何。
2. 保留既有导航断点和列宽 Token。普通内容、私信和现有宽管理页在异步页面模块交付前即可确定外框；不根据 DOM、API 响应、加载时长或业务权限重新决定布局。
3. 右栏在当前登录账户首次实际需要时才建立，之后使用 `v-show` 隐藏保留；手机和首次直达私信不为隐藏右栏取数，换号或登出卸载旧实例。临时不显示时退出布局和交互范围；其卡片继续拥有原有查询，不新增另一份推荐数据缓存。局部高度测量在重新可见时恢复，隐藏零高度不成为吸顶偏移依据。右栏恢复可见时复用相同原生透明度动效，隐藏不等待离场动画。
4. 路由内容从 `--twitter-route-entry-opacity`（当前 `0.7`）到 `1` 轻淡入，使用既有标准时长 `180ms` 和 `--twitter-ease`。只修改当前路由内容的绘制透明度，不改变布局、滚动、指针或键盘语义，不等待动画结束才发出请求。
5. 动效通过 Twitter 专属的 DOM 协调处理当前活动内容及必要的加载交接，不修改共享 RouterView，不添加业务实例或依赖 Vue 私有字段。快速导航取消旧动画及观察任务，完成、停用和卸载均恢复终态并清理资源。
6. 关闭 Misskey 动画偏好或系统要求减少动态效果时直接呈现终态。运行时偏好变化也应取消正在执行的转场，不保留半透明页面。
7. 初屏、同根节点和保持同根的 query 更新不播放主路由淡入；真实换根的占位、最终页和 KeepAlive 回访可播放。标签切换、时间线正文横移、位置恢复、查询和消息阅读租约维持各自所有权；路由淡入不成为这些行为的调度源。原生 UI、实验叠层、独立页面窗口和匿名入口／匿名内容不接入主路由淡入。

## 未采用的方案

- 保留异步 `needWideArea` 布局判断，仅加入淡入：列宽变化仍然存在，只是被透明度变化遮掩。
- 在普通页和私信页重复维护右栏显示规则：会产生第二份路由展示分类，并使首次进入和返回行为分离。
- 往返私信即销毁并重建右栏：会重置搜索等临时 UI，并重复启动卡片已有查询。
- 为路由出口增加完整地址 key、重建 RouterView 或双份业务树：会改变 KeepAlive、业务查询、流订阅和阅读租约。
- 将新内容从完全透明、位移或缩放开始：增加空白感或几何感知变化，与本次稳定页面框架的目标无关。
- 等待接口、模块、图片、骨架最短显示时长或动画结束再提交路由：将展示时序反向耦合到业务加载。

## 验证边界

真实后端浏览器专项观察私信与普通页面往返的首帧、加载占位和最终页面，确认相同目标外框在异步阶段保持一致，右栏实例复用且不重复触发其卡片初始化查询。宽视口、紧凑视口和移动布局已执行；真实换号／登出后的右栏隔离及两个管理宽页本轮仅作源码核查。

动效验证须采样真实动画的开始、中间和完成状态，覆盖首次进入、缓存回访、占位交接、同路由通知、快速连续导航、动画偏好与运行时减少动态效果。静态终态 diff 不能证明中间帧，也不能证明没有重复业务实例。焦点和交互在非零透明度期间仍应可用，主滚动恢复与私信阅读条件不得受动画时序驱动。

固定视口 before／after／diff 用于审阅本轮变化，不自动成为 P-19 全站批准基线。Linux Chromium 的运行结果不替代 Safari、Windows 常驻滚动条或移动真机核验。当前实现契约见 [route-entry-motion.md](../route-entry-motion.md) 与 [scroll-layout.md](../scroll-layout.md)。
