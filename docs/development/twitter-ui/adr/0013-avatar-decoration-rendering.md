# ADR-0013：Twitter 头像挂件的场景与绘制边界

- 日期：2026-10-21
- 状态：采纳
- 范围：Twitter 主内容头像、共享紧凑身份头像及挂件预览
- 当前实现：[Twitter 头像挂件显示与素材坐标](../avatar-decoration-rendering.md)

## 背景

人工核查发现，佩戴圆环后个人资料挂件越过主列并压住用户名，帖子头像挂件侵入正文，转发、引用和导航小头像也出现装饰。基线 `6caad7ecfa` 的公共头像沿用 Misskey 两倍图片画布约定：`width:200%; top:-50%; left:-50%`。当前使用的 1254 × 1254 透明素材可见图案基本占满画布，两者叠加造成外溢。

该约定对按相同比例制作的素材仍然有效。问题不通过修改全局缩放比例解决，也不通过为整个页面或帖卡设置 `overflow:hidden` 遮蔽。当前保存链路已有权威账户更新入口，无需引入第二份状态或迁移状态框架。

## 决策

1. 在 Twitter 业务层增加头像组合组件，基础头像通过公开 `decorations=[]` 关闭自动挂件，独立挂件层负责几何、偏好与失败呈现。基础头像的内部逻辑保持原样。
2. 展示角色仅有 `none`、`note`、`profile`。独立列表宿主显式启用主作者角色；引用和紧凑身份关闭。纯转发递归转交主作者角色，不能以 `!embedded` 或无 `replyId` 代替展示语义。
3. 保持现有头像尺寸、正文间距和两倍素材坐标。根据现有四向留白限制最终绘制区域，不让挂件参与布局尺寸计算。使用共享 token 让实际页面与预览一致。
4. 继续使用透明图片和现有佩戴协议。校准本次不匹配的圆环，使用新图片 URL 更新原挂件 ID，不批量修改其他素材。上半部挂件保留透明下半部，不根据 alpha 包围盒重定位。
5. 管理与试戴显式选择实际目标场景，保留明暗背景说明及边界示意。管理替换当前佩戴素材后重新读取服务端用户投影，再更新既有账户状态。
6. 本次不引入 PAG。动画格式不能解决布局原点、宿主边界或显示范围；在明确动态素材需求后另行设计动画资源、静态 fallback 和有限播放预算，不预建无消费者开关或播放器接口。

## 边界

- 本次修改限于被涉及的业务头像消费点，不整改 Misskey 全仓。
- 用户／佩戴权威类型来自 `misskey-js`，新增领域类型只表达展示角色及只读预览。
- 默认 UI 继续使用现有头像表现。共享组件只接收 Twitter 展示条件，不改变其业务命令。
- 头像显示偏好、减少动态图片和头像节流继续生效；编辑预览可显式绕过隐藏挂件偏好，但不绕过静态图片策略。
- 成功业务行为以真实后端回归证明；静态节点存在或图片加载不替代实际几何和回访验证。

## 中文资源与交付检查

用户已确认本次包含中文场景标签、素材说明与保存反馈的方案；本轮相关键同时维护日文源和中文资源。该例外限于已授权的头像挂件修复，不扩展到其他功能。仓库 locale safety 检查器保持原样，因 `zh-CN.yml` 报告的失败在交付时单独记录，不伪报整套检查通过。
