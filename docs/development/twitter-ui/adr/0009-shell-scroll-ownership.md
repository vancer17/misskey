# ADR-0009：Twitter Shell 主滚动归属

## 状态

已采纳。变更日期：2026-10-16。当前实现契约见 [scroll-layout.md](../scroll-layout.md)。

## 背景与证据

用户在个人资料及编辑页人工核验发现：中间栏右侧的原生滚动条占位使横幅、页头和内容无法抵达该栏的内容右缘。用户提供的 X 截图把页面级滚动条放在浏览器内容窗口最右侧；截图证明位置目标，不证明 X 的内部 DOM、滚动宿主或长右栏滚动算法。

任务开始前，Twitter 根容器固定 100dvh，三栏填满高度，RouterView 和标准 `._pageScrollable` 页面根均有独立高度与 overflow 约束。全局 `._pageContainer` 同时存在尺寸查询和 size/paint 隔离。Nitter 的自然增长布局与此嵌套内部滚动机制不同，因此仅修改页面 padding、横幅宽度或 scrollbar 样式不能完成迁移。

既有 `frontend-shared/js/scroll.ts`、流式时间线、下拉刷新和追加跟随等消费者以 HTMLElement 滚动宿主为主。`useScrollPositionKeeper` 又按每个页面元素持有 scrollTop；多个缓存页直接共用该保存器会争抢同一个宿主。上一项 ADR-0008 已修复的缓存回访及身份同步必须保留。

## 决策

采用 Twitter Shell 作用域内、横跨可用视口的浏览器原生 HTMLElement 主滚动容器；中间普通路由页面恢复自然高度，三栏宽度和页面尺度继续使用 Nitter 来源 Token。局部定位 frame 让宿主的 offsetTop 原点不受应用标题栏影响。

滚动位置协调只在主 Shell 建立一次，按实际路由地址保存有限的纯 UI 位置与 DOM 锚点；同步保存旧几何，DOM 提交及后续尺寸变化驱动恢复，用户输入取消待恢复任务。不通过业务 loading、Bootstrap readiness 或运维探测决定滚动。

解除高度和隔离的 CSS 只作用于带有明确标记的主路由出口及标准页壳。共享 RouterView、MkAvatar、分页器、滚动工具、模态组件内部业务逻辑不改。标题栏、移动常驻导航和全局弹层位于长内容之外。

## 被替代／未采用的方案

| 方案 | 未采用原因 |
| --- | --- |
| 隐藏中间滚动条、加负 margin 或按滚动条宽度补宽 | 没有改变滚动归属；依赖操作系统和叠加滚动条模式，且损害可发现性 |
| 自绘右侧滚动条、转发 wheel 到中间栏 | 引入双滚动状态、触摸／键盘／惯性同步与可访问性负担 |
| 全局开放 html/body，迁移成 document 滚动 | 超出 Twitter 局部范围；既有元素滚动消费者与其他 UI 必须广泛改造 |
| 给所有缓存页的旧 keeper 注入同一个宿主 | 多个恢复回调争抢一个 scrollTop，晚到任务可能覆盖用户操作 |
| 移除全部 overflow 或所有 contain | 会破坏页面窗口、弹层、控件滚动、反向列表、媒体裁剪和宽度查询 |
| 关闭 KeepAlive 或随机 key 强制重建 | 丢失页面／输入状态，并掩盖而非修复布局与恢复问题 |
| 用主流页面的自然高度样式直接覆盖 StackingRouterView | 它实际使用绝对定位叠层卡片；结构不同，须单独设计，不能静默改写存量偏好 |

## 保留与移除条件

独立页面窗口继续使用原滚动宿主与保存器；这是同时存在的产品能力，不是临时架构开关。`experimental.stackingRouterView` 仅保留现有卡片边界，不新增配置或扩大消费者。后续只有完成叠层专项布局和回访／手势验收，才能移除这项兼容边界。

右栏短内容吸顶、长内容按测量高度设置负 top 后停留，保证底部可访问；未建立方向状态机。若以后要实现 X 的更细滚动表现，应另补实测行为证据，而不是把本方案声明为 X 内部实现。

## 验证口径

滚动几何、键盘／滚轮、页面回访、首拉／重取、模态边界、移动导航、流式新帖及分页通过真实后端用例验证。原资料修复、匿名入口与会话恢复用例继续回归。

固定测试账号、相同视口和同一后端内容的任务开始前 Shell 快照／当前 Shell 对照用于检查预期视觉变化。原生占位式滚动条从中间栏迁出，中间栏宽度 Token 不变；有意卡片留白不得清除。候选截图和差分不能自动更新已批准基线。
