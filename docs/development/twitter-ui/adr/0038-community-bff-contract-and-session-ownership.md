# ADR-0038：社区 BFF 契约与请求归属

状态：已采纳；交付范围为契约与适配，业务挂载和真实后端验收另行完成。

## 背景

宠物 App 负责登录与外部认证，社区静态子制品没有自己的登录入口。原站以 Misskey token 和本地账户缓存判断请求归属，直接改 API 地址会导致凭据泄露、迟到结果误提交，或已成功的结果被丢弃。App 的既有 HTTP client 具有自己的业务信封，不能直接用作 Misskey 传输。

## 决策

1. 新建 `community-bff-contract` 工作区，以 domain Schema 定义版本化控制协议并派生类型、解析器、OpenAPI。账户、实例、业务请求及流频道复用 `misskey-js` 权威类型。完整账户／实例校验器从同一 SDK OpenAPI 构建生成，运行时不编译 Schema 或执行动态代码。
2. 宿主提供一次性 grant 能力；社区兑换短期凭据。续期必须再获得新 grant，不依赖过期旧 bearer，也不得复活已撤销会话。长期 App 凭据和 Misskey token 留在宿主／BFF；短期 bearer 仅在社区传输闭包中。
3. 社区目标以编译期公开接缝接管 HTTP、上传、流连接、URL-preview、账户与实例。原站目标沿用原认证路径。禁止用运行开关切换内部认证架构，禁止给 `$i` 填入假 token。
4. 一个文档只建立一个账户运行身份。请求归属为账户 ID 与不透明对象；凭据轮换代次只在传输内部比较。续期保持同一业务事实容器，旧凭据的迟到 401／409 不得破坏新凭据。撤销、换号要求销毁整个子文档，避免既有模块单例捕获旧账户。
5. 复用 Misskey 现有 Vue／Pizzax 状态架构；不为本次接入引入平行 Pinia 账户、聊天或通知副本。传输 DTO 经校验、复制后安装，业务只读模型的更新走原状态所有者。
6. 会话已建立不等于业务已挂载。当前明确保留 `COMMUNITY_APPLICATION_ADAPTER_REQUIRED`，不发送翻转 READY 或活动 ACK。后续需要真实的独立初始化与副作用释放实现，不能直接删除门槛。

## 外部依赖适配

`reconnecting-websocket@4.4.0` 的异步 URL provider 拒绝后没有释放连接锁，也不处理 provider 等待期间的取消。SDK 新增的可选 provider 路径在失败时退避重试，关闭时取消等待；没有 provider 的原站路径保持原行为。该适配仅覆盖实际使用版本的缺陷，不扩大为通用重试框架。

移除条件：升级后的依赖原生支持 URL provider 失败后重新连接及等待期间关闭，并通过当前初次失败、重连失败、恢复和关闭回归测试；届时移除 SDK 内该补偿路径。

## 后果与验收边界

构建新增契约生成依赖，生成校验器与协议制品留在忽略目录，CI 应从源码重建。完整上游 OpenAPI 是协议参考，不能当 BFF 授权列表；端点、频道和资源权限由 BFF 按真实账户授权。

Mock 只证明协议、序列化、适配及取消行为。真实 BFF／Misskey 的双用户隔离、读写、上传、私信、通知和后台恢复，以及 H5／Android 装配仍须独立验收。iOS 真机后置；M09 减少运动分支仍未验收通过。
