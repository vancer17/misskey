# ADR-0032：Twitter 搜索移除原生选项表单并保留分页工具条

## 状态

已采纳（2026-10-25，项目所有者要求按讨论方案实施）。

## 背景

Twitter 帖子搜索复用原生结果页时，同时呈现“选项”折叠表单和分页工具条。表单包含起止时间、搜索范围、主机及用户选择；下方工具条包含排序、日期定位和刷新。所有者在人工核查后明确要求移除前者，保留后者，本次不新增另一套高级搜索界面。

Nitter 并非没有高级筛选：`external/app/nitter/src/views/search.nim` 的 `renderSearchPanel` 将筛选、排除项、时间范围和最低点赞数放入搜索框下的折叠面板，样式由 `src/sass/search.scss` 提供。移除原生表单、保留现有工具条属于本项目的产品选择，不声明为完整复刻 Nitter，也不以未经测量的 X 行为作为依据。

两处时间控件的语义不同。原生表单的 `rangeStartAt`、`rangeEndAt` 限定搜索结果时间窗口；分页工具条的 `initialDate` 映射为 `sinceDate` 或 `untilDate`，设置分页起点。保留工具条不表示其日期控件等价替代完整起止时间筛选。

## 决策

1. Twitter 自动搜索不挂载整个原生“选项”表单，不采用 CSS 隐藏，不增设替代筛选入口。手动表单的时间范围字段不进入 Twitter 自动请求。
2. 保留结果列表的现有分页工具条及其排序、日期定位、刷新交互，继续消费同一个分页器。本次不扩展搜索提供方能力，不重写共享基础组件内部逻辑。
3. `userId`、`username`、`host` 路由条件继续解析并参与查询。用户解析取消、标识优先、权限检查及失败时禁止放宽范围等规则沿用 ADR-0031；移除可见表单不取消已有有效条件。
4. 默认 Misskey 手动搜索保留完整表单、起止时间请求字段及手动提交，不将 Twitter 展示取舍扩展到其他界面。

## 验证边界

真实隔离后端验证原生表单及字段未挂载、下方工具条保留并继续发送当前查询、路由筛选有效及解析失败不放宽、自动请求不携带手动时间范围字段。默认 Misskey 验证完整表单和手动搜索，中文及窄屏场景复用现有语言回归。

视觉 diff 使用同一合成数据、语言、视口、DPR、主题和字体，审阅“选项”行移除及下方内容上移；搜索框、标签、快捷提示、分页工具条和首帖作为相邻对照。结果以交付记录为准，不预先声明测试通过，也不替代 P-19 全站视觉基线。

现行行为见 [Twitter UI 搜索](../search.md)，保真偏离登记见 [移植保真审计 H-5](../port-fidelity-audit.md)。
