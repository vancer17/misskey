# ADR-0012：统一头像挂件管理页面与管理编辑器

- 日期：2026-10-20
- 状态：采纳
- 范围：实例头像挂件管理页、新增／编辑弹窗、对应文案与真实后端回归
- 当前实现：[头像挂件管理](../avatar-decoration-management.md)

## 背景与证据边界

人工核查路径为个人资料的装饰入口进入 `/settings/avatar-decoration`，再点击管理入口进入 `/avatar-decorations`，随后点击添加打开管理编辑器。路由定义同时将 `/admin/avatar-decorations` 指向同一个管理页。

提交 `406d94a608e1896d23404baf75b721094d8cd672` 优化了设置页及试戴弹窗，管理页 `pages/avatar-decorations.vue` 和管理编辑器 `pages/avatar-decoration-edit-dialog.vue` 未纳入该次改动。因此，从已优化的设置页进入管理功能，仍会进入另一套页面内容和表单布局。

主滚动修复 `0ca88b2d49aa55a703d93cd5c057719fcac21dec` 针对 Twitter 主视口中的路由 outlet。相应滚动布局规则有明确作用域，独立窗口及全局弹层不在该作用域内。这一修复不能直接证明管理编辑器的内部滚动与页脚布局已经得到覆盖。

排查同时确认以下事实：

- `MkWindow` 已具有 Twitter 外观分支。不能把问题归因为窗口组件完全没有 Twitter 皮肤。
- 全局样式对 `html`、`body`、`main`、`div` 声明了细滚动条及滚动条颜色；窗口内容元素属于该选择范围。仅凭截图中的原生滚动条外观，无法断言全局选择器没有命中。
- 管理页原有页面间距、卡片以及编辑器内的表单布局和 sticky 操作区仍由各自内容实现。窗口外壳具有主题支持，仍不足以保证内部内容与其他前端页面一致。
- 全局弹层具有自己的实际 DOM 位置。管理页的局部类不能直接成为弹层内容的祖先样式；这不等同于 Teleport 导致全局主题丢失。
- 既有设置回访测试通过管理 API 新增目录条目后返回设置，只验证了回访读取，并未操作管理页的添加按钮和管理表单。

上述证据将本次改动聚焦到实际管理页、编辑器和缺失的操作链路测试。

## 决策

### 1. 复用页面壳，保持单一目录归属

Twitter UI 下的管理页复用公开导出的 `TwitterSettingsShell`；默认 UI 保留 `PageWithHeader`。两者共享同一份管理内容与命令，工具栏直接提供数量、刷新和文字添加入口。

目录继续归属现有管理页面，类型复用 `misskey-js` 的管理目录响应。分类使用只读派生视图，不新增 Pinia、镜像实体类型或第二份目录状态。编辑器仅持有草稿，父页提供可以等待的写入命令，并绑定不可由草稿修改的实体 ID。

### 2. 新增和编辑统一使用模态编辑器

管理编辑器使用既有 `MkModalWindow`，桌面配置为 `440×620`，复用其正文和独立页脚结构，以及既有手机抽屉行为。表单正文负责滚动，错误反馈与保存、取消、删除按钮放在 `footer`。

该选择提供与已优化试戴入口一致的模态结构。它允许移除业务编辑器自行维护的 sticky、高层级和模糊背景操作区，同时保留基础组件的窗口交互实现。本次不修改基础 `Mk*` 组件的业务逻辑。

在编辑器实际内容和页脚内接入基础输入控件需要的 Twitter 主题变量，保持主页面及弹层各自的布局边界。正文继续使用既有全局滚动条规则，不扩大主路由滚动选择器，也不添加隐藏滚动条的全局规则。页脚是否发生额外溢出通过实际尺寸断言和截图检查。

### 3. 区分写入确认和目录刷新

创建接口返回完整实体，可以使用真实回执加入目录；更新接口没有实体响应，更新后必须重新读取。删除由打开编辑器时绑定的 ID 执行，在成功回执后移除该条目，再读取目录。

写入开始前使旧读取失效。写入失败由编辑器展示并保留草稿；若失败发生在首次目录读取被打断之后，重新启动首拉，避免取消编辑器后出现无状态的空白区域。写入成功而随后读取失败时，关闭已提交编辑器，在管理页明确显示“已保存／已删除，列表刷新失败”。该情况下不把刷新失败重新抛成写入失败。

路由激活重新读取，离开时取消读取并释放局部弹窗。请求身份、页面活动状态及账户身份共同防止迟到结果覆盖新的目录。

### 4. 角色选择以 ID 草稿为准

传入实体的角色 ID 数组复制成局部草稿。角色目录仅提供名称和候选，不作为保存时重建选中 ID 的数据源。元数据加载失败时保留原 ID 并显示说明，只有用户明确移除才改变选择。

名称与图片地址沿用既有请求协议的非空要求；图片预览失败提供重试并保留草稿。关闭、选择角色、删除确认、写入和关闭动画共用临时操作边界，避免重复提交及未完成写入时关闭。

### 5. 设计依据与本次语言例外

颜色、间距、圆角及触控尺寸复用当前 Twitter tokens。仓库的间距和布局基准是 `external/app/nitter`；本次管理业务视图以已有前端基础设施组合实现，没有引入一个声称来自 Nitter 的头像挂件管理页面，也没有把未实测的 X 行为作为证据。

用户已确认包含中文文案的修复方案。本次 `_avatarDecorationManager` 文案按该授权同时接入 `ja-JP` 和 `zh-CN`，并生成对应语言类型。此授权例外仅覆盖本次管理功能的中文资源；仓库非日文资源安全检查的规则保持原样。检查器报告应在交付时如实说明，不通过修改检查器消除这项记录。

## 验证与影响

新增 `avatar-decoration-manager.spec.ts`，通过真实隔离后端账户、角色和上传图片，操作实际添加、编辑、删除按钮及表单。目录 API 可用于建立起始状态和核验结果；成功业务响应不由 Mock 生成。失败与竞态测试仅中断网络或延迟真实响应。

当前测试文件包含 14 个执行场景，覆盖目录状态、取消、完整管理链路、权限相关角色读取、写入失败、写入成功后读取失败、首次读取被失败写入打断、回访旧响应、默认 UI 和两条路由，以及桌面亮暗和手机布局。手机环境采用 Chromium 移动模式、触控及手机 UA，包含打开后横屏。

视觉证据同时包含截图和可观察几何：正文承担纵向滚动、页脚没有实际第二处溢出、按钮和反馈在视口内、全局滚动条 computed style、双预览背景的实际颜色以及真实图片解码。输出截图不会自动成为已批准基线；像素对照和相应平台原生滚动条外观仍需按验收环境审阅。
