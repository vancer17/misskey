# ADR-0010：写入失效、数据所有者与计数展示边界

- 日期：2026-10-18。
- 状态：实施于当前工作区；具体校验结果由任务最终报告记录。
- 范围：Twitter 发布／回复／关系及回访新鲜度，明确触及的保留页面局部。

## 背景

原资料页在全局弹窗发布后没有更新，需要切到别页再返回。已有 `notePosted` 成功信号，但资料分页器没有消费；回访修复不能替代原地写入后的反馈。横向检查又发现回复树只在挂载加载、人员名单独立于统计、频道统计与流式集合脱节、空结果被非空守卫跳过、社区嵌套管理／收藏集合回访遗漏。

原 `useNote` 深拷贝输入，动态捕获仅覆盖反应、投票和删除。仅重取父组件实体不能保证现有卡片回复／转发数更新。置顶真实回归进一步显示：主页置顶区已更新但菜单仍是“置顶”，因为原命令忽略了返回的 MeDetailed；需将原回执提交到账户更新入口，而不是猜测 pinnedNoteIds 或增加重复读取。

## 决策

1. 复用既有发帖、删除、反应、账户和关系事件。只有置顶、收藏、Clip 等原命令确有实际消费者而缺少成功通知时，才在现有 EventEmitter 中补小范围类型化事件。通知定位失效范围，查询负责最终事实。
2. 保留页面实体、Paginator 与原流式组件的数据归属。抽取仅包含 UI 调度信息的刷新组合函数，不建立统一业务状态机、Query 框架或新状态依赖。Pizzax 的持久化偏好不承载临时查询投影。
3. 对共享 useNote 没有动态来源的回复／转发数，建立引用计数回收的会话级只读字段投影。同一查看者及原帖共享请求；字段从唯一 Note 类型派生，不作为动作或权限输入，不创建完整帖子模型副本。
4. 回复树由各查询节点更新。已经展开的子节点独立刷新，未展开节点不预取；本人对节点回复时展开该节点，仍遵循原深度限制。使用稳定实体身份，不用随机 key 或整页重建刷新。
5. 空数组是成功查询结果，不是“未加载”的替身。已存在的非空刷新守卫在本次触及局部退役。原生 init、翻页、标签显隐与回访共享忙闲协调；请求期间的新写入保留下一次意图。
6. Mentions／Direct Notes 直接复用已有流式源，不再手写另一套 mention 监听及轮询。反应／转发人员名单在非实时模式沿用原轮询档位，限定当前标签，不能仅由总数推断成员未变。
7. 保留 ADR-0005 的聚合流边界和既有搜索／热门快照语义。不把本次修复变成实时订阅架构迁移或结果重排策略变更。
8. 置顶命令的 MeDetailed 先经原 `updateCurrentAccountPartial` 提交，再通知主页失效。收藏／Clip 仅在原 API 成功分支通知消费者；Clip 菜单不再本地猜测成员数。

## 未采用方案

| 方案 | 不采用原因 |
| --- | --- |
| `await os.post()` 后统一刷新 | 弹窗关闭包含取消；还让全局导航耦合具体页面 |
| 每次成功重载全部分页器 | 无关请求、并发 init、滚动跳动，且不覆盖旧快照字段 |
| `nextTick` 或强制重绘 | 不会产生缺失的数据与事件消费 |
| 修改共享 MkPostForm／MkPagination／useNote | 侵入既有基础组件业务，扩大变更面 |
| 随机 key、关闭 KeepAlive、整页重载 | 丢失草稿、线程和缓存语义，掩盖失效归属 |
| 客户端插入所有标签／计数加一 | 复制查询过滤和业务规则，不正确处理排序、权限及多账号 |
| 每张卡片单独轮询 | 请求随重复显示与列表规模放大 |
| 新建完整 NoteStore／Pinia | 现有数据归属足够；不为计数字段另建业务架构 |
| Mock 成功链作为业务验收 | 不能证明真实回执、过滤、时序、流式和缓存交互 |

## 统计口径复核

扩展撤销转发回归时，原先假设“本人转发增加一，撤销归零”不符合当前后端：`NoteCreateService` 排除本人转发与机器人，删除路径也没有转发计数递减。用例改为验证删除外壳后对实际原帖发起重新确认，并与 `notes/show` 一致；不通过前端加减改变后端业务口径。该后端语义不在此次前端修复中改写。

## 真实回归揭示的提交竞态

频道统计用例曾出现新帖已显示、频道数量仍为零。原 `NoteCreateService.create` 在插入帖子后便返回，通过 `setImmediate` 执行的后台链才累加用户、父帖及频道统计。前端正确消费发布事件并立即查询，仍可能取得旧值。

因此，局部调整本地提交边界：帖子、投票和原统计规则使用同一事务管理器提交，再返回成功。异步通知、索引、排行、时间线缓存和联邦投递保持原位置；不等待全部后台任务，不改变统计口径，不添加延时重试或架构切换开关。代价是创建请求等待这组本地数据库写入，未声称对多副本或外部系统提供原子性。

另以真实浏览器连续回复和传输中断复现了计数投影的在途失败窗口：第一个计数请求失败时，不能搁置期间收到的第二次发布意图。调度改为只检查是否存在新意图，不再以旧请求成功作为消费新意图的前提；失败本身仍不产生新意图。

## 命令拒绝分支

真实置顶上限拒绝测试显示：`apiWithDialog` 会显示错误，但仍返回原拒绝 Promise。新增的单参数 `then(success)` 产生了另一个没有拒绝处理的 Promise，导致页面全局错误。局部成功分支补齐原请求的拒绝处理，由原对话框继续呈现错误；不刷新、不伪造成功、不修改共享 `os.ts` 或菜单组件，也不以宽泛 catch 隐藏成功回调本身的程序错误。

## 影响与边界

核心基础组件、全局分页器、共享 useNote、既有认证引导、Nitter 模板、Token 和样式块不修改。代价是集合 reload 仍清空再加载；本次不伪装为深分页窗口无损增量同步。

部分原删除通知只有 ID，当前实体统计采取保守重取；未建立全站依赖索引，也不承诺任意第三方跨设备回复／转发全量实时。用户关系／媒体／权限最终判断仍属于既有后端和调用链。
