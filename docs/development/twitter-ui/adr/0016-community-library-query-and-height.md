# ADR-0016：所属频道采用预读分页，资料库窗口按内容收敛

- 日期：2026-10-21
- 状态：采纳
- 范围：`/channels` 的所属频道查询、管理／收藏窗口表现及原界面 owned 消费入口
- 当前实现：[频道入口布局与请求边界](../communities-layout.md)
- 关系：细化 [ADR-0015](./0015-community-strip-layout.md) 第 4 项的窗口表现，局部替代第 6、7 项中所属频道由原分页器持有查询的约定；首页／发现横条、帖子流与搜索决策继续有效

## 背景

人工检查“我的频道”窗口时，四条频道下方出现大片留白；点击“查看更多”没有新增条目，按钮及其区域随后消失，留白进一步增加。两个现象来自不同机制，不能仅靠给列表补高度或保留按钮解决。

窗口原调用固定 `600 × 650px` 的 `MkModalWindow`。少量内容结束后，固定高度主体仍占据剩余空间；业务根节点使用 `--twitter-bg`，窗口主体使用 `--twitter-panel`，剩余区域因此还形成明显的上下色块。主体同时使用 `flex: 1` 和 `container-type: size`，只把根高度改成 `auto` 不足以获得正确的内容高度，因为块方向尺寸隔离仍存在。

所属频道原先由 `Paginator('channels/owned', { limit: 10 })` 管理，使用默认的保守耗尽策略。非空首批即使不足十条也不会确认结束；四条频道因此仍保留后续加载能力。点击后，分页器以现有游标请求更旧条目，收到空数组才关闭后续能力，`MkPagination` 随之隐藏加载区域。按钮消失是耗尽状态的呈现，根因是首屏没有后续存在的证据；固定外框则放大了区域消失后的视觉空白。

共享分页器的另一种数量探测还使用内部固定阈值。把所属频道直接切到该策略，会遇到调用方页大小与阈值不一致的问题。即使阈值改成实际请求数量，返回恰好十条时也不能区分“总共十条”和“还有第十一条”。

## 决策

### 1. 用所属频道专用适配器确认后续页

保留 `channels/owned` 接口及既有 `misskeyApi` 鉴权、取消能力。适配器每页展示 10 条，请求 11 条；返回数量大于 10 才产生下一游标，游标取最后展示的第 10 条 ID。额外的第 11 条不另存缓存，也不能用作下一游标，避免排他游标跳过该条目。

该端点按所属用户和非归档条件过滤后取上限，再完整打包频道数组，且允许的 limit 上限覆盖 11，因此本次不需要新端点或后端协议改动。频道实体直接使用 `misskey-js` 的权威类型。

### 2. 页面保留唯一所属频道查询

新增 `ui/twitter/store/owned-channels.ts`，`channels.vue` 创建并持有一个查询实例。原界面的 owned 标签和 Twitter 管理窗口全部迁移到这个实例，不通过 UI 开关在两套 owned 查询实现间切换，也不保留另一份旧 `ownedPaginator`。

已确认快照只包含条目和可空下一游标；`hasMore`、展示状态及条目引用从权威状态单向派生。未成功取数的 `null` 快照与成功空集合分开表示。`initialize` 只接受未初始化状态，失败不因关窗重开自动重试。`retry` 重放失败的首拉／刷新或追加操作；追加失败保留列表与游标，刷新成功才替换快照。

追加在途时拒绝重复动作；显式刷新递增请求世代并取消旧请求。成功、失败及 `finally` 清理均验证世代，旧响应不能污染刷新结果或清除新请求状态。当前取消恢复请求前的已确认状态。关闭窗口不销毁查询，页面卸载才 dispose；回访复用现有 `useTwitterRefresh` 的可见性、忙闲和首拉协调，不伪造 `IPaginator` 能力。

### 3. 弹层消费稳定的只读投影

`TwitterCommunityLibraryView` 只包含 `items`、`status`、`hasMore`。宿主向 `os.popup` 传稳定的 computed ref，窗口持续读取当前值，不传递打开瞬间的 `.value` 快照。组件只发出追加、重试、导航和关闭意图。

收藏继续由原一次性分页器持有，宿主 computed 映射为同一展示契约，后续能力为 false；不为收藏建立新的集合所有者。两种资料库共用紧凑加载、空态、错误态和非空结束提示。加载更多期间保留列表并禁用按钮；失败展示局部重试，而不是据此判为结束。

异步操作替换或移除按钮时，展示层通过共用的 `useChannelLibraryFocus` 衔接键盘焦点：优先进入第一条新增频道，其次为重试／当前操作和状态区域。用户已经移动焦点、窗口正在退出或入口不可见时不抢回。该逻辑只保留一次交互的 DOM 阅读位置，不持有另一份请求或频道状态。既有基础模态通过 `inert` 隔离背景，业务资料库补上自身的 Tab／Shift+Tab 首尾循环，控件资格复用 `isFocusable`；基础模态继续负责背景隔离、Esc 及关闭恢复。

### 4. 基础窗口增加显式内容高度表现

给 `MkModalWindow` 增加 `heightMode: 'fixed' | 'content'`，默认 fixed。资料库显式使用 content，沿用 `width=600`，将既有 `height=650` 作为桌面最大高度。实际类型为 dialog 时，根高度为 auto，上限为 `min(650px, 100%)`，复用原覆盖层的可用高度。

只有启用内容模式的 dialog 主体使用 `flex: 0 1 auto`、`min-height: 0` 和 `container-type: inline-size`，保留宽度容器查询并允许由内容决定自然块高度；footer 不收缩。根 `contain: content` 不包含尺寸隔离，继续保留。默认固定窗口、移动抽屉及安全区不改变，不全局替换所有窗口的 container-type。

业务内容、紧凑状态与基础窗口统一使用 `--twitter-panel`。`TwitterPageState` 的整页最小高度仅由资料库作用于其公开根元素的局部样式收敛；不修改全局空态尺寸，不用私有 CSS Modules 类名的深层覆盖，不增加 JavaScript 测高。

这次基础组件扩展只处理布局，不改变焦点、Esc、遮罩、inert、关闭过渡或 `os.popup` 释放时机。

## 未采用的替代方案

- **直接修改共享 Paginator：**其请求规模、双向加载、部分响应及多个现存消费者并不等同于所属频道。固定阈值问题可独立修复；本次不把所有消费者迁移到预读策略，也不扩大到通用分页重构。
- **只修正数量阈值：**仍无法确认恰好整页时是否存在后续条目，不能消除稳定数据集下的无效探测点击。
- **继续使用 MkPagination 并适配完整 IPaginator：**会为这个单向查询增加未使用的新页、队列等能力。业务窗口和原 owned 标签直接消费真实查询动作与只读状态即可。
- **业务弹窗测高或覆盖基础私有类：**已有 flex、最大高度和内滚动可表达目标；新增测量生命周期与私有结构依赖没有必要。
- **全局改为内容高度：**会改变默认固定窗口及抽屉行为。内容高度作为显式表现能力，仅由需要它的调用方启用。

## 后果与验收边界

稳定数据集下，0、4、10 条在首屏即可确认结束；11、20、31 条分别通过 2、2、4 次请求读完，不需要再点一次空页探测。若预读之后后续条目被删除或归档，下一请求仍可能合法为空，此时保留现有列表并收敛到结束状态；N+1 不承诺并发变化时每次点击都会新增条目。

短列表窗口按内容收敛，长列表和矮视口由主体滚动；移动抽屉继续保留其既有高度，但列表及余留主体使用连续的 panel 表面。`650px` 只是沿用现有窗口数值作为上限。当前 X 归档 HTML 保存失败状态，不能证明该管理窗口的成功 DOM 或尺寸，不能将本决策描述为 X 实测高度复刻。

验收需在真实隔离后端覆盖分页边界、失败重试、重复动作、刷新与追加竞态、关闭重开、创建后回访和原界面 owned 入口。视觉检查覆盖短／长列表、矮视口、明暗主题、移动抽屉以及既有默认固定高度窗口。用例与证据入口见当前实现文档；本 ADR 不记录尚未发生的执行结果。截图和 diff 用于人工审阅，不自动升级为已批准基线。
