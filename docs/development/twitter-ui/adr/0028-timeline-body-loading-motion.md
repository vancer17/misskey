# ADR-0028：时间线来源切换的正文与加载交接

## 状态

已采纳（2026-10-23，项目所有者要求按讨论方案实施）。

范围为 Twitter 首页时间线的来源切换。标签指示条继续遵守 ADR-0027；通知、频道及个人资料的正文切换不纳入本次修复。

## 背景

ADR-0027 只把各标签独立的下划线替换为共享指示条，没有改变正文的生命周期。首页原先仅在用户开启横向滑动时挂载 `MkSwiper`；手势关闭时，来源切换直接重建正文。不同来源的查询 key 包含来源及筛选，重建能隔离请求归属，但也会经历旧列表卸载、初始骨架、实际结果三个阶段。

人工核查和本地浏览器排查显示，快请求仍可能使骨架短暂闪现；深滚动时，较短的骨架会收缩可滚动高度，浏览器随之夹紧主宿主位置。仅增加指示条动画或等待固定时间不能解决这两个交接问题。

ADR-0018 反对复制帖子集合、双分页器和 DOM 快照来维持查询结果。本次沿用该数据边界：退出阶段只让 Vue 已有的离场 DOM 短暂保留，不克隆 DOM，不保留其组件、订阅或查询所有者作为业务缓存。

## 决策

1. 点击切换的正文动画和手势识别分别控制。多来源时间线挂载同一个 `MkSwiper`，手势及对应 `touch-action` 限制仍遵守既有横向滑动偏好；正文动画同时遵守动画偏好及减少动态效果。`MkSwiper` 只增加可选展示参数、局部 CSS 参数和过渡生命周期事件，其他消费者保留既有默认展示参数。
2. 横向转场只有一个所有者，不在列表内部叠加第二个横移。Twitter 使用既有 `180ms` 正常时长、既有缓动和零额外间隔；这些是项目参数，不宣称是 X 移动端实测值。
3. 新查询立即创建并发出请求。完整查询 key、接口映射、分页、订阅、队列、手动刷新及旧请求归属保护继续由既有所有者负责；不通过删除 key 或推迟请求掩盖跳变。
4. Twitter 加载边界直接消费查询所有者的 `initializing`。共享流式组件提供保留默认内容的加载插槽，Twitter 包装层接管骨架呈现；帖子、空态和错误仍由原列表判断。不根据条目数、DOM 或 Promise 完成复制加载事实。
5. 骨架按既有快速时长 `120ms` 延显。快请求直接进入实际结果，慢请求显示骨架；完成时交叠淡出骨架并淡入结果。没有最短骨架停留时间，没有等待横移动画完成的请求门槛；动画关闭时直接显示正确终态。
6. 来源切换采用新来源回顶策略；离开和回访时间线路由仍遵守 Shell 的路由位置恢复。切换前测量旧正文可见位置，离场 DOM 暂时冻结为 inert、`aria-hidden` 的视觉层，随后通过窄接口原子地取消当前待恢复任务并立即回顶。离场层补偿回顶造成的纵向位移，新面板从顶部进入；Shell 捕获恢复锚点时排除离场 DOM，防止在转场中立即导航时把旧来源片段解释为新来源位置。
7. 展示层只保留必要的 DOM、几何及可取消的 UI 任务，不建立按来源的列表缓存或位置表。快速切换只保留一个旧离场层与一个当前层；下一次来源提交前通过 `MkSwiper` 的公开离场结算入口调用 Vue 公开完成回调，不依赖旧 CSS 动画已经建立，也不直接移除 DOM。任务必须验证当前归属，结束、取消、停用和卸载均释放临时约束。用户接管滚动后，异步结果不能再次回顶。
8. 真实独立窗口沿用原滚动 keeper 的锚点算法，只增加待恢复任务的窄取消能力。来源回顶先清除旧锚点和保存位置，并作废已排队的 `nextTick` 及延迟任务；普通回访仍按原算法恢复，不让旧任务在新来源回顶后再次移动窗口。

## 未采用的方案

- 在点击或请求前固定等待：延后真实反馈，仍不能保证结果在等待结束前到达，也不能阻止高度收缩。
- 删除查询 key 复用旧分页实例：会混淆来源、账户及筛选归属，扩大业务修改范围。
- 让骨架至少显示一段时间：把快请求的结果人为滞留，延显与淡入已能处理短暂闪现。
- 复制帖子数组、克隆 DOM 或为每个来源保留分页器：增加第二份事实、订阅或缓存策略，超出本次视觉交接需求。
- 在请求完成后再次回顶：会覆盖用户已接管的滚动位置，并让快慢请求产生不同导航行为。
- 保存完整旧列表高度：产生与实际内容不符的长空白，临时几何只服务当前可见区域与转场。

## 验证边界

现行契约见 [时间线正文与加载转场](../timeline-body-motion.md)。正文中间帧、骨架交接和真实滚动宿主的高度／位置曲线应与标签指示条终态截图分别验证。实际业务结果继续由真实后端集成用例证明；传输延迟只改变响应到达时机，不代替后端响应。

本 ADR 不预先声明测试或平台验证通过，局部截图不自动成为阶段正式视觉基线。
