# ADR-0023：Twitter 简介标签统一进入帖子结果页

## 状态

已采纳（2026-10-23，项目所有者要求按讨论方案实施）。

## 背景

人工核查发现，个人资料简介中的 `#test` 点击后显示旧版用户卡片。Twitter 个人主页、共享用户结果行及频道简介均向既有 MFM 传入 `isNote=false`，MFM 因此生成 `/user-tags/:tag` 链接；目标页调用 `hashtags/users`，查询简介含标签的用户。该结果符合 Misskey 原有用户标签语义，但与 Twitter 界面的帖子标签导航目标不一致。

阶段清单未纳入 P-16 用户标签页，而可见简介入口仍能到达该页。仅改个人主页会留下搜索、关注／粉丝列表、二维码用户结果及频道简介中的相同入口；仅适配目标页样式仍会保留查询用户的行为。

## 决策

1. Twitter 界面的个人简介、共享用户结果行及频道头部和“关于”页简介中的标签，统一导航至 `/tags/:tag`，复用 P-15 既有帖子查询和页面状态。
2. 在 `TwitterHome.vue`、`ui/twitter/UserResult.vue`、`TwitterChannel.vue` 的四处 MFM 调用显式传入 `isNote=true`，并以中文注释说明标签导航意图。该公开参数负责现有标签路由选择，不把简介转换为帖子事实。
3. 标签识别、URL 编码和站内导航继续由 MFM 与 `MkA` 负责。保持基础组件内部逻辑、默认 Misskey 界面、后端用户标签索引及 `/user-tags/:tag` 路由的既有实现。
4. P-16 继续不纳入；本次处理归属 P-15 的入口语义与路由泄漏闭合，不新增 Store、领域模型、包装组件或运行时开关。

## 未采用的方案

- 在通用 MFM 内按 Twitter UI 改写路由：业务界面的导航选择可由公开参数表达，无需扩大共享基础组件职责。
- 保留简介的用户标签导航并适配 P-16：只改善旧页面表现，无法满足本次统一查询帖子语义的目标，也会扩大页面范围。
- 仅修改个人主页：共享用户结果行与频道两处简介仍可进入用户标签页。
- 新增标签包装组件或重复解析 MFM：增加同一标签链接的第二套规则，现有公开能力已经足够。

## 后果与验证边界

Twitter 简介标签与帖子正文标签共享帖子结果页；默认 Misskey 用户标签功能继续可用。代码入口调整不改变简介原页面布局，导航目标的表现由既有 Twitter 标签页承担。

验收需以真实后端证明标签匹配帖子和无匹配帖子时的空态，并检查各入口、中文标签编码、键盘激活及返回导航；默认界面保留用户标签导航的对照验证同样必要。Mock 只能证明协议或映射，不能替代这些业务行为证明。本 ADR 不将尚未执行的运行验证或截图 diff 记为通过，正式视觉基线仍遵守 P-19 的阶段出口条件。
