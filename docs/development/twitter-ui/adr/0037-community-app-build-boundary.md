# ADR-0037：社区本地子制品与无会话启动边界

## 状态

已采纳（2026-10-27，项目所有者要求实现社区专用构建）。

## 背景

宠物 App 已有 H5／Android 本地装配与双面翻转验证。要随 App 交付真实 Twitter 社区代码，需要从 Misskey 的服务端 HTML、启动配置、完整路由和浏览器账户恢复中分离构建入口。BFF 会话与传输实现尚未完成，无法诚实地提供真实用户或业务就绪状态。

## 决策

1. 添加固定的社区构建目标，复用无环境 IO 的编译工厂；原站点入口保留原有部署行为。以编译期适配器选择嵌入边界，不引入运行时新旧架构开关。
2. 生成独立 `built/community-app/` 静态制品，沿用现有语言内联器，首版包含中文、英文和日文。禁止外置模块与原站点启动根进入输出图；最终文件逐项校验 SHA-256 及引用闭包。
3. 同时编译最小 Bootstrap 与真实 Twitter 应用图，HTML 只执行 Bootstrap。真实 BFF 尚未提供时停在 `SESSION_REQUIRED`，保留明确的依赖失败，不创建假账户或认证成功消息。
4. Bootstrap 独占宿主参数、语言、装配身份和启动状态。业务组件与 Store 不接收运维探测；App 同源子窗口只向冻结 API 交付一次参数。
5. 以专用内部路由及命名空间存储隔离同源宿主；不复用完整站点的认证、管理与全局副作用启动链。IndexedDB 不增加切换存储后端的兼容行为。
6. 输出目录和执行证据继续忽略，源码与交接文档只描述当前能力。H5／Android 业务与设备验收待真实 BFF 接入；iOS 真机和 M09 减少运动债务继续后置。

## 未采用的方案

- 复制后端渲染 HTML、运行时改写绝对资源 URL：会继续依赖服务端启动与部署结构，难以核验静态闭包。
- 先执行原站点 Bootstrap 再隐藏登录或其他 UI：账户恢复、路由及存储副作用已经发生。
- 用假用户或模拟认证响应使业务根挂载：不能证明真实会话与业务生命周期，也会掩盖 BFF 未完成的事实。
- 将完整设置／管理路由导入后再过滤：不可达能力仍进入构建图，扩大嵌入边界。

## 影响

当前可交付并校验完整本地资源及无会话启动边界；用户进入真实社区仍需要下一阶段真实会话和传输装配。交接接口与命令见[社区专用构建文档](../community-app-build.md)。
