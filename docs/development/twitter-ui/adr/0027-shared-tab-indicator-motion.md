# ADR-0027：共享横向标签指示条转场

## 状态

已采纳（2026-10-23，项目所有者要求按讨论方案实施）。

第 3 条中保留各页圆角的部分由 [ADR-0029](./0029-tab-indicator-shape-consistency.md) 补充，指示条现统一仅圆上角。

范围为 Twitter UI 的时间线、通知、频道入口、频道详情及个人资料标签栏。只改变选中指示条的运动，不重新裁决标签布局，也不修改 Misskey 基础组件的业务逻辑。

## 背景

这些标签栏原来分别在每个按钮或链接上绘制选中态 `::after`。切换时旧元素的下划线消失、新元素的下划线出现；给各自的伪元素加过渡仍无法形成从旧位置到新位置的连续横移。

ADR-0021 解决的是侧栏胶囊与频道入口指示条的局部尺度。其不引入共享组件和 DOM 测量的决定针对当时的两个局部样式修复。本次新增了五排标签共用的横向运动需求，需要在不复制业务事实的前提下测量实际按钮位置；ADR-0021 中已经确定的等分布局和双侧内缩继续有效。

## 来源证据

- Nitter 的 `external/app/nitter/src/sass/timeline.scss` 以等分 `.tab-item` 和底边框呈现导航选中态。项目继续以其空间关系及现有 Token 为尺度依据，不通过动效引入新的标签宽度或图标展开规则。
- 本地 X 归档 `tmp/community_for_x/abs.twimg.com/responsive-web/client-web/sharedbundle.Communitiesbundle.UserLists.9bb579fc32d96cb9a.js` 的模块 `262461` 使用每个标签自己的选中线，未提供本次共享指示条横移动画。
- 同目录 `sharedbundle.MLBGamebundle.MLBHubbundle.NBAGamebundle.NBAHubbundle.NFLGamebundle.NFLHubbundle.NFLTop10.61e3baad11e0ced4a.js` 的模块 `443582` 使用唯一指示条，按选中节点计算 `left` 与 `width`，并以 `250ms ease-in-out` 过渡；首次测量与减少动态效果分别处理。这是 X Web 其他模块的实现先例，不能当作截图中 X 原生移动端社群的实测行为。
- 提供的移动端截图可观察选中位置、文字和图标的终态，不能推导精确时长、缓动曲线或中间帧轨迹。

## 决策

1. 每排标签只绘制一个 `TwitterTabIndicator`，从 `ui/twitter/index.ts` 导出。组件接收原始展示键 `activeKey: string | null`，通过所在标签容器内的键标记查找 DOM；不持有业务选中值，不导入用户、频道或分页类型，不建立新的业务 Store。
2. 原按钮、链接、路由、ARIA、焦点与事件归属保持现有实现。个人资料保留 `MkA` 和路由派生的选中态，频道保留其既有键盘与面板关联。视觉组件只跟随页面已经确认的选中值，不在点击时另存乐观选中状态。
3. 按实际 DOM 测量指示条位置与宽度，保留小数精度，并补偿容器边框和横向滚动。通知两侧各内缩 `14px`，其余四排各内缩 `12px`；保留各处既有 `4px` 高度、颜色和圆角。个人资料的 `position: sticky` 不被公共样式覆盖。
4. 以 `transform` 横移、以 `width` 调整长度；默认使用项目已有的 `--twitter-duration-normal`（`180ms`）和 `--twitter-ease`。这些是项目暂定动效参数，后续可按实测校准，不宣称是 X 移动端的测量结果。不使用 `transition: all`，不缩放标签或正文。
5. 只有同一有效标签结构中的选中值变化播放转场。首次挂载、重新挂载、尺寸或字体变化、标签集合变化以及 KeepAlive 恢复均直接校准终态。快速切换时从当前呈现位置转向最新目标，不排队、不通过动画完成通知驱动业务。
6. DOM 提交后合并测量任务，以尺寸及节点观察处理布局变化；停用和卸载时释放观察器与待执行任务。不存在或无法测量的目标不产生错误的零位置动画。遵循用户的动画设置和 `prefers-reduced-motion`，关闭动效后仍更新正确终态。
7. 横向溢出时只调整该标签栏自身的可见范围，不调用可能移动 Shell 主滚动宿主的 `scrollIntoView()`。重选回顶、内容切换、请求、订阅和已读处理仍由原所有者负责；现有正文 `MkSwiper` 不额外叠加过渡。

## 未采用的方案

- 分别给每个按钮的 `::after` 加过渡：两个独立元素无法在不同位置之间连续横移。
- 新建统一业务 Tabs 模型或 Store：五排只共享几何与动效需求，统一业务状态会扩大边界并复制既有权威事实。
- 按标签序号和平均宽度计算位置：无法覆盖长文案、动态标签、真实小数宽度及横向溢出。
- 同时加入正文滑屏、触摸跟手和选中标签展开：这些有独立的交互与布局要求，超出此次指示条转场范围。
- 等待动画结束后更新路由或内容：把业务时序绑定到呈现时序，会影响快速切换、减少动态效果和原请求归属。

## 验证边界

现行接入契约见 [横向标签指示条转场](../tab-indicator-motion.md)。终态几何检查和运动中间帧检查分别进行：静态截图不能证明连续运动；Mock 响应不能证明频道、个人资料或通知业务行为。

回归需覆盖桌面／移动布局、明暗主题、动画偏好、快速切换、动态标签、搜索恢复与 KeepAlive 回访，并确认个人资料路由和频道键盘语义保持有效。正式视觉基线仍按阶段计划管理，本次局部 before／after／diff 不自动批准 P-19 基线。实际通过、失败和未执行项记录在本次交付结果，不在 ADR 中预先声明。
