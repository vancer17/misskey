## 缓存机制与职责

常规 `components/global/RouterView.vue` 使用 KeepAlive + Suspense，缓存标识为 `route.viewKey ?? fullPath`。离开缓存页不等于卸载，局部状态、路由监听和响应式依赖可以继续存在。当前用户路由共享 `viewKey: 'user'`，不同账户请求必须按账户归属判断是否仍可回填。

身份展示、数据集合新鲜度和路由容器恢复是三个独立职责：

| 职责 | 当前实现 |
| --- | --- |
| 本人身份展示 | `useTwitterDisplayUser` 从既有 `$i` 单向派生只读展示引用；其他作者保持输入模型，Mock 保持样本，不新增用户缓存 |
| 资料写入 | `settings/profile.vue` 等待原 API 确认后，经 `updateCurrentAccountPartial` 提交账户；头像、横幅、基本资料、扩展字段共用串行保存入口 |
| 设置页缓存恢复 | `settings/index.vue` 仅接受 settings 路由更新本地子页展示引用；无有效子路由时不新建 NestedRouterView；停用页不触发无关重定向 |
| 主页资料刷新 | `user/index.vue` 在实际停用后回访加载；成功才替换缓存，取消／忽略失效账户请求 |
| Twitter 时间线刷新 | `TwitterUserTimeline.vue` 以停用、活动标签和分页器占用状态调度；空列表参与刷新，隐藏 v-show 面板在显示时消费待刷新意图 |

展示身份不合并回 note，不反馈到回复、转发或权限规则。普通帖、置顶帖、折叠转帖、引用帖和转发者标签分别以实际作者身份选择展示来源；基础头像和共享 useNote 内部逻辑不变。

## 本次局部刷新契约

首次初始化由既有 MkPagination 负责；没有实际停用标记时，activated 不增加初始化请求。实际停用后，当前标签优先刷新，其他已挂载标签保留待刷新意图。标签切换会消费其意图，不能把 v-show 误认为 v-if 重挂载。

条目数量不是初始化状态：已经返回空数组的列表同样需要回访检查。调度依赖既有分页器的 fetching/fetchingOlder/fetchingNewer，不与初次加载或翻页并发 init。

`Paginator.reload()` 仍是先清空再加载的既有契约。错误状态及手动重试仍归原分页器，不称为“失败保留全部旧列表”的软刷新；不会建立无限自动重试。主页 users/show 使用成功回填的软刷新，两者语义不混淆。

附件标签请求遵循当前 `users/notes` 约束：`withFiles: true` 时不同时启用 `withReplies`。未增加后端协议或前端兼容开关。

其他旧页面仍可能使用首次 activated 跳过和非空才刷新等不同策略；这些是其现状，不是可直接复制到新增功能的统一规范，本次没有进行全仓迁移。
