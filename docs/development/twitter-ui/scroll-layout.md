# Twitter UI 主滚动布局

## 当前契约

Twitter 普通内容布局采用全视口原生元素滚动。`ui/twitter.vue` 的 `[data-twitter-scroll-viewport]` 横跨可用窗口宽度，包住三栏；滚动条在窗口内容区右缘，不占用中间栏。真正的宿主是该 HTMLElement，不是 document；`window.scrollY` 不作为主滚动位置。

根 Shell 保持一屏高度。可选应用标题栏和移动常驻底栏在主滚动内容外，占用其自身高度。视口在相对定位的 frame 内绝对铺满，保持既有滚动工具使用的局部坐标原点。三栏宽度、断点、头像、字体、卡片间距继续消费既有 Token；主列与内容尺度来源为 Nitter，左侧栏和右栏宽度属于既有 X 信息架构映射，具体来源见 [保真审计](./port-fidelity-audit.md)。

Shell 的普通内容、私信与现有宽管理页分类由 `ui/twitter/domain/layout.ts` 的同步路由展示策略提供。目标页面模块的加载占位和最终内容使用相同外框；页面元信息继续服务标题等展示，不决定列宽和右栏存在性。`/admin/emojis2` 与 `/admin/job-queue` 保留不显示右栏的既有宽页约定，其他管理页不扩大该规则。路由内容的 [轻淡入](./route-entry-motion.md) 只修改绘制透明度，不参与布局、请求或滚动恢复。

## 页面表现边界

`ui/twitter/scroll-layout.scss` 只在主视口的 `[data-twitter-route-outlet]` 内解除标准路由出口及 `._pageScrollable` 页壳的固定高度和页面级纵向滚动。路由出口保留 inline-size 查询能力，外层确定高度的视口提供 cqh 基准。共享 RouterView 的 size/paint 隔离只在此主出口内覆盖；共享组件内部代码及全局 style.scss 未修改。

这条规则不移除 textarea、代码块、媒体裁剪或反向列表的局部 overflow；不作用于独立页面窗口和全局弹层。编辑页原有卡片留白仍保留，不能把卡片留白误当作滚动条区域清除。

主视口使用 `scrollbar-gutter: stable`；传统滚动条在外侧预留位置，叠加式滚动条遵循浏览器平台表现。不使用隐藏滚动条、固定像素补宽、滚轮转发或自绘滚动条。

## 位置恢复

`provideTwitterScrollHost` 只在 Twitter 主 Shell 建立一次。其位置表为当前会话内有界的 UI 数据，按主路由完整地址区分页面，去除入口 `ui` 参数。不同用户、不同用户页签不能仅用共享的 `viewKey: user` 合并位置。

同完整地址的重复路由通知不启动滚动导航，也不取消已有的位置恢复任务。附件预览关闭后经历史记录同步原地址时保持当前位置；主导航显式重选，以及导航去除入口 `ui` 参数但位置键不变时，继续沿用回顶行为。

导航同步阶段，在旧页面仍可测量时保存 scrollTop、可见 DOM 锚点标识与相对偏移；纯绘制的时间线离场层不参与锚点捕获。DOM 提交后恢复目标页。未有位置记录的新页面从顶部开始。回访过程中列表重载、图片或异步组件改变高度时，由尺寸／DOM 观察继续对齐锚点；恢复不轮询接口状态、不解析业务响应、不修改分页器。

滚轮、触摸、指针与键盘输入表示用户接管位置，立即取消待恢复任务。后续异步内容不能重新拉回旧位置。主导航重选取消恢复并回顶，停用的 Twitter 页面壳不操作当前宿主。

`useTwitterScrollPositionKeeper` 在主出口内将位置恢复交给 Shell。真实存量的独立页面窗口使用不同路由器，继续沿用原 `useScrollPositionKeeper` 的锚点算法，新增的取消入口仅用于显式来源切换时作废旧恢复任务；不会让所有 KeepAlive 页面同时监听和修改一个主 scrollTop。

首页时间线的 [来源切换](./timeline-body-motion.md) 属于同路由内的新查询，采用新来源回顶。时间线壳先测量旧正文可见几何，再通过窄接口原子地取消 Shell 当前待恢复任务并立即回顶；旧离场 DOM 仅保留短暂视觉位置补偿，不加入路由位置表或分来源缓存。回访路由仍走上述恢复契约，首拉结果、错误或图片到达后不再次回顶，用户接管滚动后旧交接任务不能移动宿主。

## 左右栏与移动布局

左侧导航沿用既有内容与必要的局部溢出，在主视口内吸顶并保持可用高度。右栏不再建立第二条普通页面滚动链；短栏吸顶，超过可用高度的长栏随主内容滚动、底部抵达视口后停留。负 top 由实际元素高度派生，不使用滚动方向状态机，也不宣称复刻未经测量的 X 右栏动效。

右栏在登录账户首次实际需要时挂载，之后在该账户内隐藏保留；手机布局和首次直达私信不启动隐藏卡片的查询。普通页与私信往返复用同一右栏及原卡片查询，换号或登出卸载旧实例。隐藏时退出布局和交互范围，零高度不覆盖可见时的有效测量；恢复时重新测量。右栏可见时的局部轻淡入不延迟隐藏，也不成为卡片的业务生命周期。

完整左侧栏宽度为 `275px`，图标侧栏为 `72px`，侧栏根节点内距为 `8px`。导航链接保留整行点击区域；其内部胶囊按图标、文字和未读提示的内容宽度布局，最大宽度受链接约束。悬停、选中与键盘焦点的视觉反馈作用于胶囊，长文案可省略，链接仍提供完整可访问名称。完整侧栏的发帖按钮占内宽的 `90%` 并沿逻辑起点对齐；在无局部滚动条占位的 `275px` 侧栏中，按钮宽度约为 `233.1px`，距主列边框约为 `33.9px`。图标模式继续使用 `52px` 控件并居中。侧栏、主列和右栏之间的栅格位置不依赖这些内部控件宽度，主列仍为最大 `600px`；未读提示与点击意图不增加业务状态副本。来源及边界见 [ADR-0021](./adr/0021-sidebar-capsules-and-community-tab-indicator.md)。

移动导航位于长内容之外，仍使用现有高度及 safe-area；普通内容页的发帖 FAB 保留既有定位。主页面头部和标签吸顶参考外层视口，既有 MkStickyContainer 内部逻辑不变。时间线、通知、频道及个人资料的 [共享标签指示条](./tab-indicator-motion.md) 只测量标签几何；横向溢出时仅调整标签栏自身的滚动范围，不移动主滚动宿主，个人资料标签容器仍保留 sticky。

## 模态交互

全局弹层宿主位于主视口之外。Shell 对已有可见模态背景的呈现状态建立局部 inert 背景边界，关闭后撤销；没有模态背景的 tooltip 不锁定主内容。此处理不更改宿主 overflow，所以弹层期间新挂载的滚动消费者仍能找到同一个 HTMLElement。

弹层内部滚动、选择文件、输入、焦点管理继续使用 Misskey 原实现；独立页面窗口也不纳入主视口位置表。主界面与弹层尺寸变更的观察器在所属组件销毁时释放。

## 范围与保留边界

普通主出口覆盖个人资料、编辑资料／设置、时间线、通知、帖子详情、搜索、标签、关注列表、频道／社区页面。匿名欢迎入口不接管；匿名公开内容沿用普通内容布局。

私信路由使用 `[data-twitter-layout='messages']` 有界工作区，不消费普通主滚动位置，也不解除其局部 overflow。收件箱和会话列表分别滚动，跳入私信前保存普通页位置，返回时按原契约恢复。私信工作区不使用实验叠层出口，因此不会同时存在另一份活动会话或阅读租约；存量叠层偏好继续用于普通页面。布局、键盘及标读约定见 [messages.md](./messages.md)。

私信复用同一组 Shell 导航和列宽：视口达到 `1280px` 时显示 `275px` 完整导航，将既有 `600px` 主列与 `350px` 右栏合并为最多 `950px` 的消息工作区；其收件箱消费既有右栏宽度，会话使用剩余约 `600px`。`950px` 只由现有 Token 相加派生，不建立另一份权威常量。`501–1279px` 使用 `72px` 图标导航和最多 `600px` 的单栏工作区。分栏的 `918px` 判定针对消息工作区的实际容器，不是新的视口断点。移动设备判断、收件箱保留底栏、会话隐藏底栏、所有私信页隐藏 FAB 的边界保持原有行为。

消息页头复用共享 `50px` 高度和 `18px` 标题 Token，收件箱筛选复用 `TwitterTabIndicator` 的几何与动效契约。这里的尺度统一不改变工作区的一屏高度、收件箱／消息的独立滚动、编辑器对可视视口与 safe-area 的处理，也不改变活动页面的业务租约和显式标读条件。历史取舍见 [ADR-0034](./adr/0034-messages-shared-shell.md)。

主路由轻淡入不修改共享 RouterView、KeepAlive key 或页面业务实例，也不借动效结束重新回顶或标读；存量叠层、匿名内容和独立页面窗口继续沿用各自边界。同步布局与动效的当前约定、已执行验证及待真机核查范围见 [route-entry-motion.md](./route-entry-motion.md)。

既有 `experimental.stackingRouterView` 为真实存量的绝对定位卡片视图，当前保留有界面板与内部滚动，未静默切换用户偏好。它不是新旧业务架构开关，也不是主视口实现的回退开关。只有后续为叠层设计并验收完整的外侧滚动行为后，才能移除该边界；当前不宣称叠层也实现窗口右缘主滚动。

## 回归入口

`packages/frontend/test/e2e/twitter-scroll.spec.ts` 使用隔离真实后端、真实帖子与实际 DOM，检查主视口几何、滚轮／键盘、吸顶、缓存回访、列表重取、用户取消恢复、移动底栏、模态边界、实际分页／新帖排队，以及页面窗口和既有叠层。测试显式保留占位式原生滚动条，不能用默认隐藏滚动条的无头截图替代几何断言。

`twitter-profile.spec.ts` 继续证明头像／昵称同步、编辑页反复返回和草稿保留，不能因滚动迁移而取消这些业务回归。匿名入口与会话恢复原用例也必须保持通过。

固定数据与相同视口的 before/after/diff 是待审阅证据，不自动批准正式视觉基线。Linux Chromium 结果不替代 Windows 常驻滚动条、Safari、移动真机软键盘和触摸惯性核验。具体执行结果保存在本次交付报告，不将未执行的平台写成通过。

侧栏空间回归覆盖 `1280px` 与 `500px` 布局边界两侧、长文案、未读徽标及键盘焦点。完整侧栏需分别测量整行链接和内部胶囊，确认两者的点击与视觉边界；对比截图同时核对主列边框位置，避免把侧栏内部留白变更误实现为全局列间距变更。

历史方案与选择理由见 [ADR-0009](./adr/0009-shell-scroll-ownership.md)。
