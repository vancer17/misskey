# 头像挂件管理

本文描述头像挂件管理页及新增／编辑弹窗的当前实现。Twitter UI 的显示范围、素材坐标及裁剪规则见 [头像挂件显示与素材坐标](avatar-decoration-rendering.md)；管理流程的设计决策和历史排查记录见 [ADR-0012](adr/0012-avatar-decoration-management.md)。

## 页面入口与职责

| 入口 | 页面／组件 | 职责 |
| --- | --- | --- |
| `/settings/avatar-decoration` | `pages/settings/avatar-decoration.vue` | 查看目录、试戴及管理本人佩戴；具有管理权限时显示管理入口 |
| `/avatar-decorations` | `pages/avatar-decorations.vue` | 实例挂件目录的读取、分类，以及新增、编辑、删除命令 |
| `/admin/avatar-decorations` | 同一管理页 | 管理路由别名，共用目录与操作逻辑 |
| 管理页的“添加”或挂件卡片 | `pages/avatar-decoration-edit-dialog.vue` | 素材上传／选择、未保存的表单、双背景佩戴预览、角色选择和提交反馈 |

管理页通过 `ensureSignin()` 获取当前账户，管理入口条件为 `isAdmin || policies.canManageAvatarDecorations`。缺少管理权限时显示权限说明；API 继续执行服务端权限校验。页面离开及账户身份检查用于阻止旧读取结果写回当前页面。

Twitter UI 使用从 `ui/twitter/index.ts` 导出的 `TwitterSettingsShell`；默认 UI 使用 `PageWithHeader`。两个外观分支共享同一份目录、工具栏、状态呈现和业务命令。工具栏提供数量、刷新和带文字的添加按钮。分类由目录派生为 `Map`，分类名称保持普通文本语义；卡片使用原生按钮，支持键盘操作。

## 目录与写入回执

目录的唯一页面状态位于 `avatar-decorations.vue`，类型直接使用 `Misskey.entities.AdminAvatarDecorationsListResponse`。分类、计数和卡片都是该目录的只读展示。编辑器接收实体及可等待的 `submit`／`remove` 命令，只保存临时草稿。

| API | 回执及当前处理 |
| --- | --- |
| `admin/avatar-decorations/list` | 返回目录；成功后替换本页目录，失败保留已有结果 |
| `admin/avatar-decorations/create` | 返回完整实体；创建确认后可加入该实体，随后重新读取目录 |
| `admin/avatar-decorations/update` | 没有实体响应；使用打开弹窗时绑定的 ID 更新，并重新读取目录取得最新实体 |
| `admin/avatar-decorations/delete` | 删除确认后移除已绑定的 ID，再重新读取目录 |
| `admin/roles/list` | 提供角色名称与新增候选；不会反向覆盖表单已选择的角色 ID |

创建请求类型直接使用 `Misskey.Endpoints['admin/avatar-decorations/create']['req']`。父页绑定待编辑或删除的实体 ID，表单不能改变操作对象。更新接口没有实体回执，因此请求字段不被拼接成“已更新实体”。

写命令开始时使旧目录读取失效。写入确认之后，目录刷新即使失败，提交命令仍按写入成功完成：编辑器关闭，管理页提示“已保存，列表刷新失败”或“已删除，列表刷新失败”，用户通过刷新取得完整目录。这个边界避免把刷新失败呈现为需要再次提交的创建失败。

若更新或删除的挂件正在当前账户上佩戴，写入确认后还会请求真实 `i` 回执，通过既有 `updateCurrentAccountPartial` 更新账户的 `avatarDecorations`，使已佩戴头像使用服务端确认的新图片或移除结果，不从表单 URL 拼装账户事实。账户刷新失败单独提示，不改变已确认的写入结果；管理页的刷新按钮可重新读取目录和当前佩戴。账户身份检查及佩戴快照比较阻止旧回执覆盖其间已确认的新佩戴状态。

## 加载与失败状态

| 状态 | 页面行为 |
| --- | --- |
| 首次读取中 | 显示加载状态 |
| 首次读取失败 | 显示错误说明及重试入口，不显示成功空态 |
| 已确认的空目录 | 显示空目录说明，并保留添加入口 |
| 已有目录刷新中 | 保留已有内容，刷新按钮禁用 |
| 已有目录刷新失败 | 保留目录并显示刷新失败提示 |
| 写入失败 | 编辑器保留草稿并显示错误；如果写入打断了尚未完成的首拉，恢复目录读取 |
| 写入成功、刷新失败 | 关闭已提交的编辑器，在管理页明确提示写入已确认及刷新失败 |
| 路由离开 | 取消读取、释放本页弹窗；已发出的写请求继续等待后端完成 |
| 路由回访 | 重新读取目录，包括上次结果为空的情况 |

挂载和首次激活共用 `activate()`，避免重复首拉。每次读取具有独立 `AbortController`；请求身份、页面活动状态和账户身份共同限制结果交付。失效响应即使迟到，也不能覆盖后续读取。

## 编辑器与表单

新增和编辑共用 `MkModalWindow`，桌面配置宽度为 `440px`、高度为 `620px`，视口约束及手机抽屉行为由既有模态组件处理。表单位于正文滚动区；保存、取消、删除及写入错误位于独立 `footer` 插槽。基础模态组件保留原实现。

Twitter 内容区域就地映射基础输入组件需要的主题变量。颜色、间距、圆角和触控尺寸复用现有 Twitter tokens；正文滚动条沿用全局 `scrollbar-width: thin` 和 `scrollbar-color` 规则。页脚自身的基础 `overflow: auto` 保留，实际是否发生第二处溢出由几何验收检查。管理页不把主路由滚动规则扩展到弹窗。

素材区位于表单首部，以“上传素材”为主按钮，提供“从网盘选择”作为另一入口；“使用图片地址”默认折叠，展开后可手动填写。三种入口均写入同一个 `url` 草稿，编辑已有挂件时直接使用原地址。上传与网盘选择仅接受图片素材，保留真实 `DriveFile.url`，不使用缩略图地址、临时 Blob 地址或文件 ID 代替现有 API 字段。

本地上传直接调用既有 `uploadFile`，沿用账户上传目录、容量和服务端文件策略。原始文件直接传输，不经过裁剪、压缩或水印处理。浏览器明确提供非图片 MIME 时在表单内提示，MIME 为空时交由服务端识别；真实回执仍按图片类型和非空原图地址采纳。上传进度及取消按钮就近展示；原生文件选择取消不进入忙碌状态，上传中取消会中止本次传输，失败保留原有素材及其他字段，同一文件可以重新选择。每次上传以返回句柄区分，取消或卸载之后到达的旧进度和回执不能覆盖新草稿。网盘弹窗通过公开的 `done`／`closed` 事件收尾，选中真实图片后更新地址并提示尚未写入挂件目录，取消不替换素材，关闭动画结束后恢复表单。

Twitter 编辑器在已有素材时增加“校准当前素材”。专用业务弹窗复用 Cropper.js，生成符合原生两倍画布约定的静态透明 PNG，再由原编辑器上传并更新同一 URL 草稿；应用校准与保存目录是两个独立提交边界。校准取消或失败保留原素材，已上传原图继续保存在网盘；已有挂件保存时沿用原 ID，并复用目录和当前佩戴的真实回读。制作规格、格式及跨域边界见 [素材校准](avatar-decoration-rendering.md#管理页面内校准)，历史决策见 [ADR-0014](adr/0014-avatar-decoration-material-calibration.md)。

素材上传成功只准备图片草稿，并明确提示添加或保存后才更新挂件目录。用户取消新增／编辑会丢弃该表单草稿，已经上传到网盘的文件仍由网盘管理；不会为了取消挂件草稿额外删除真实文件。新建按钮文案为“添加挂件”，编辑时继续使用“保存”。

表单还包括名称、分类、描述和可用角色。名称与图片地址按现有请求协议检查非空；名称、地址和分类去除首尾空白，空分类提交为 `null`，描述保留输入内容。手动地址入口保留现有兼容行为；图片加载失败提供本地说明和重试，保留全部草稿，图片可访问性不构成额外的保存规则。

角色 ID 数组是选择的唯一依据，并从传入实体复制。角色目录仅用于显示名称和提供公开角色候选。元数据读取失败时保留已选择 ID，显示未知角色信息，仍允许用户明确移除该 ID。角色选择、删除确认、写入及关闭动画共用临时操作状态，防止重复提交或关闭中再次提交。

遮罩点击、Escape 和取消按钮进入同一个关闭处理。提交或删除尚未完成时，操作按钮禁用，关闭按钮隐藏；成功后关闭，失败后恢复可操作状态并保留草稿。删除操作使用 `os.confirm`，取消确认不会发送删除请求。

预览区域显示“佩戴效果预览”标题，并说明使用当前头像展示同一挂件在两种背景下的效果。没有素材时显示明确空态，不展示容易误解为已选挂件的两张头像；有素材后显示“浅色背景预览”与“深色背景预览”两张卡片。两张卡片使用同一图片草稿，分别声明亮色与暗色 `color-scheme`，不修改管理员实际佩戴的挂件。验收读取最终 computed background color，并确认真实挂件图片成功解码。

Twitter 管理编辑器与试戴共用 `TwitterAvatarDecorationPreview`，可切换帖子头像（`note`）与个人资料主头像（`profile`）场景。预览和正式页面共用头像组件、尺寸 tokens 及裁剪边界：帖子头像为 `48 × 48px`，资料头像内容为桌面 `112 × 112px`、移动 `80 × 80px`，资料边框四边各 `4px`。预览同时展示相邻文字布局，并用虚线标出挂件可见边界；Twitter 目录卡片也使用正式帖子头像尺寸。默认 UI 保留既有预览。

共享上传工具仅补全传输结束行为：网络错误、中止、已有超时事件和响应 JSON 解析失败均使 Promise 完成失败收尾，保留原有成功回执、错误提示和调用签名。没有添加新的超时值、上传限额或业务数据模型。

## 验证入口

E2E 使用独立的真实测试后端，地址由既有配置固定为 `http://localhost:61812`。运行前需在测试外部准备服务器、数据库、Redis，以及完整的 `frontend` 和 `frontend-embed` 构建资源，参照 [前端测试说明](../../../.claude/skills/working-on-frontend/references/knowledge/frontend-testing.md)。前端构建与检查使用 Node 24，后端使用与当前原生依赖匹配的 Node 22；Node 版本选择、服务启动及资源准备由运行环境完成，测试代码不加入环境探测或启动流程。

后端测试配置中的公开 `url` 也需设为 `http://localhost:61812`，使真实文件回执和资源地址指向该隔离实例；测试结束后恢复本轮临时调整的配置。

测试调用测试实例的 `reset-db`，使用新建账户、真实角色和真实上传图片；成功业务响应全部来自后端。故障与竞态场景仅中断传输或延迟真实响应。素材上传、挂件保存和后续目录读取分别核验，上传成功不能替代挂件已创建的证据。

从仓库根目录执行：

```bash
pnpm --filter i18n generate
pnpm --filter frontend typecheck
pnpm --filter frontend exec vitest run --globals --config vitest.config.unit.ts test/unit/drive-upload.test.ts
pnpm --filter frontend exec playwright test --config playwright.config.ts avatar-decoration-manager.spec.ts
node scripts/check-shipping.mjs
```
