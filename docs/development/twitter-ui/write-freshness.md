# Twitter UI 写入后与回访新鲜度

更新：2026-10-18。范围：当前 Twitter 主页面与明确触及的 Compatible 局部。本文描述现行实现；方案取舍见 [ADR-0010](./adr/0010-write-invalidation-and-view-freshness.md)。既有身份展示与设置路由边界继续遵循 ADR-0008，滚动归属遵循 ADR-0009。

## 数据归属

用户／频道／Clip／主帖实体仍由原页面加载；集合仍由原 Paginator 或既有流式组件持有。没有引入 Pinia、完整帖子缓存或用户缓存。业务基础组件 `MkPostForm`、`MkPagination`、`MkNotesTimeline`、`MkStreamingNotesTimeline`、`MkFollowButton`、共享 `useNote` 与全局 Paginator 的内部业务实现不变。

`ui/twitter/composables/use-twitter-refresh.ts` 只保存待刷新、激活、请求占用等 UI 调度信息，不存实体，不决定可见性权限或集合成员。`ui/twitter/store/note-counters.ts` 是查看者范围内的计数只读投影，不持久化；类型由 misskey-js Note 派生，不能传回帖子动作或权限判断。所有新增公共入口从 `ui/twitter/index.ts` 导出。

首页 Twitter 时间线的手动刷新由注入的 `TwitterTimelinePaginator` 管理，继续复用原流式组件的接口映射、订阅、轮询及唯一分页集合；查询期间保留内容，回顶与结果提示由页面协调。其结果、并发及分页边界见 [timeline-refresh.md](./timeline-refresh.md)。

## 成功信号与消费者

| 信号／命令 | 消费范围 | 更新方式 |
| --- | --- | --- |
| 既有 `notePosted` | 发布者主页、实际被回复／转发原帖、相关频道、当前标签结果 | 发帖回执只确定失效范围；原查询裁定集合、排序与计数 |
| 既有 `noteDeleted` | 已显示帖子、已知直接回复／转发关系、当前资料统计 | 复用删除处理；统计重新查询，不本地减一 |
| `userPinnedNotesChanged` | 对应作者主页的详细实体 | pin/unpin 的真实 MeDetailed 先经 `updateCurrentAccountPartial` 提交，随后通知主页重新确认 |
| 原 main 流的 `follow`／`unfollow`／`followed`／`meUpdated` | 本人或被操作目标的用户实体与关系集合 | 请求确认后的查询结果回填；关注请求不等同于关注成立 |
| 既有反应事件 | 当前原帖的反应者名单 | 类型不变时也失效；非实时模式当前人员标签沿用原轮询档位重新确认 |
| `noteFavoritesChanged` | 已有收藏页集合 | 只有收藏／取消收藏原命令成功才触发 |
| `clipNotesChanged` | 对应 Clip 的成员集合与实体 | 原命令成功后失效，不手算 Clip 成员数量 |
| 屏蔽／拉黑页面自己的解除命令 | 原关系分页器 | 成功后调度重载，不将用户 ID 错当关系项 ID |

`os.post()` 返回只说明弹窗关闭。标签预填在关闭后清理，但关闭不再作为成功刷新依据。即时发布、回复、引用和转发沿用真实成功事件；取消、拒绝、传输失败及定时草稿保存不产生即时发布成功事实。原 `apiWithDialog` 仍返回原 API Promise；新增的菜单成功分支同时处理原请求拒绝，由原对话框显示错误，不留下未处理拒绝，也不继续成功副作用。

帖子计数沿用当前后端统计口径：本人转发不增加转发数，撤销转发也不能由前端假定应减一。计数与当前人员名单长度不保证相等；前端在原帖失效后重新读取，不越权修正后端字段。

删除事件本身只有帖子 ID。已显示关系可据原输入定位父帖；未知关系不猜测。用户与频道统计在该 ID 无法确定归属时采用当前实体的保守重取，不宣称已建立全站依赖索引。

## 本地写入完成边界

`packages/backend/src/core/NoteCreateService.ts` 将帖子、可选投票及既有用户／父帖／频道统计放在同一数据库事务内提交；`notes/create` 的成功回执发生在事务提交后。本人转发、机器人及频道参与者的原有统计条件不变，后台不再重复累加。

该局部后端修复消除了“发布已成功，但立即重取仍读到旧统计”的竞态，不使用前端固定延时或轮询等待一个猜测值。联邦投递、通知、时间线缓存、搜索索引与排行仍在原异步链中；本地事务不承诺这些系统或只读副本同步完成。没有新增 API 字段、运行开关或数据库迁移。

计数展示请求与分页刷新均只消费明确意图：请求失败时，若在途期间又发生了已确认写入，继续消费那一次新意图；没有新意图则不自动重试。

## 页面实现

### 用户主页与标签

`TwitterUserTimeline` 保留原四个分页器和 v-show 面板。实际发布者匹配当前主页时，各标签产生刷新意图；当前面板先处理，隐藏标签显示时处理。原空集合参与刷新。用户实体的 `users/show` 与列表分开更新，顶部总数不由列表长度或本地加减推算。

用户切换以真实 ID 为子列表实例边界，旧实体请求有取消与归属校验。默认用户时间线中本次触及的 notes/index.timeline 局部使用同样的空集合／忙闲原则，不改造全部默认页面。

Hashtag 页的全局、页内、移动发帖入口共用成功失效链。搜索和热门仍保持原查询快照／手动与回访边界，不在每次发帖时擅自重排。

### 详情、子回复与计数

主帖路由实体、用户／频道前后文、直接回复、展开子线程和人员名单分别拥有查询范围。父页面更新主帖不能代替子回复集合更新。

对子节点的本人回复会展开相应节点并重新查询，保持原最大深度限制；其他未展开节点不因此预取。展开状态是明确的临时 UI 状态，不以返回条目数量代替。回复加载失败保留旧集合与原错误入口，卸载和资源切换后的请求不得回填。

Twitter 动作栏显式接收回复数、转发数、反应数与本人反应等只读输入；图标、激活样式和 aria 同源。原 `useNote` 初始化快照仍供原业务动作使用，不向其中合并展示投影。计数按实际显示原帖 ID 和查看者范围共享请求，重复卡片不逐个查询；最后一个消费者释放后回收。没有每卡定时器。

回复／转发计数当前保证本地确认写入、已知删除和回访的重新确认，不承诺任意其他设备在任意他人帖子上的动作全量实时同步。反应名单与总数分别处理：反应事件使名单失效；非实时模式当前人员标签以既有轮询档位重新查询，覆盖总数不变但参与者变化。

### 通知、关系与社区

通知的全部标签保持原通知流。Mentions 与 Direct Notes 改为复用 `MkStreamingNotesTimeline` 的 mentions/directs 数据源，沿用已有查询、mention 通知和非实时轮询；删除静态分页器和重复回访路径。

关注按钮保持原业务实现；关系集合和头部用户计数分别接入关系事件及回访。普通发帖不重载关注关系集合。

频道 Home 的原帖子流不增加整表刷新；写入只补频道实体统计更新。社区页面 Home 横条、聚合流、Explore 推荐／管理／收藏集合分别调度，原空集合不会被跳过。管理／收藏折叠体的可见几何由业务包裹节点报告，隐藏时保留意图，显示后消费；不读取或修改 `MkFoldableSection` 内部状态。观察器在卸载时清理。

社区聚合流仍是 ADR-0005 D8 的纯分页＋手动／回访刷新，不建立逐频道多连接，也不在客户端合并多频道流。没有因此开放新的导航入口。

## 刷新调度契约

首次初始化仍由原加载入口负责。请求调度等待本轮 DOM 挂载完成，尊重原分页器 fetching/fetchingOlder/fetchingNewer；原生重新初始化开始时可以覆盖此前的回访意图。写入发生在查询开始后，意图不能被旧请求完成清除，结束后再查询一次。

KeepAlive 停用与 v-show 隐藏不同于弹窗遮挡。只有真实路由停用暂停页面调度；发帖成功通常发生在弹窗关闭前，不能因背景 inert 丢掉成功通知。回访依据实际停用，不统一跳过第一次 activated。

`Paginator.reload()` 仍是清空再加载，不是保留深分页窗口的软刷新。本次不承诺自动保存所有历史分页条目，也不提供新的集合状态副本。用户／频道／Clip 实体成功回填，失败保留最后实体。失败不会在同一意图中无限重试；用户重试、后续成功事件或回访负责重新触发。

原 Paginator 不支持取消，包装层不会伪造取消契约。页面自有实体和回复请求有 AbortController／目标校验。所有新事件监听和观察器有对应卸载清理。

## 验证入口与边界

专项：`packages/frontend/test/e2e/twitter-write-freshness.spec.ts`。真实独立后端、PostgreSQL、Redis 与服务端签发账户；传输中断或延迟保留真实响应，不替换业务结果。测试实例的建立、配置、端口隔离和启动准备属于外部启动脚本，业务组件及用例内不探测运维 readiness。

已有联合回归：`twitter-profile.spec.ts`、`twitter-scroll.spec.ts`、`anonymous-entry.spec.ts`、`session-recovery.spec.ts`。界面／适配单元用例只证明其本身映射或渲染范围，不替代上述多轮业务证明。

执行状态和失败边界以任务产物 `tmp/write-freshness-fix-20261018/` 中最终报告为准，不能以用例定义存在或文件名含 final 判为通过。中间失败输出不覆盖最终证据，trace 中的隔离会话资料不公开分发。

本次未调整 Nitter 源参数、Token、基础滚动组件或 Vue style 块。同条件前后截图只用作本次布局回归候选证据，不自动批准 P-19 正式视觉基线。Safari、移动真机、实验 StackingRouterView、所有默认界面及任意跨设备动作不因本次测试被宣布全量通过。
