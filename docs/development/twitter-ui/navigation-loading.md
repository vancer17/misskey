# Twitter 主路径加载与刷新

## 当前范围

频道详情、个人资料、首页时间线和通知共用 Twitter 主 Shell。普通路由切换保留 Shell、主滚动宿主和两侧栏；页面代码、实体与列表各自表达加载状态。页面尺度继续消费现有 Nitter 来源 Token。

主路由、嵌套路由和实验叠层出口接受可选 `fallback` 插槽。宿主占位沿出口子树继承；未提供时仍使用 Misskey 原加载器。Twitter 业务出口使用 `TwitterRouteLoading`，并经 `--MI-router-view-background` 统一底色。匿名欢迎入口保持自己的入口背景及原有加载器。

Nirax、路由键、KeepAlive 容量及滚动恢复规则保持既有契约。代码等待与 API 等待分别呈现，导航不等待全部业务请求完成。

## 页面加载状态

| 页面 | 代码就绪后的呈现 |
| --- | --- |
| 频道详情 | 返回头常驻；频道首拉时显示横幅、资料和列表占位；频道失败提供重试，不存在为单独终态；频道确认后列表单独加载 |
| 个人资料 | 返回头与页壳常驻；profile 骨架使用真实横幅比例及响应式头像 Token；资料成功、错误和不存在在同一页壳内交接 |
| 时间线 | 静态页面与页头常驻；来源切换使用正文横移及延显骨架，错误重试与空态由原列表判断，详见 [正文与加载转场](./timeline-body-motion.md) |
| 通知 | 路由代码按需加载；代码就绪后保留原有页头、通知骨架、错误及空态 |

Twitter 的 `MkPagination` 在加载态、错误、空态与结果之间直接交接，不使用整块 `out-in` 淡出淡入。首页时间线的初始加载边界以透明度交叠交接骨架和原列表，不改变 `MkPagination` 的状态判断。默认界面的原过渡保留，流式行级进出动画保持原有机制。

## 数据所有权与刷新

频道实体由 `store/channel-detail.ts` 的唯一查询所有者管理，适配器调用既有 `channels/show`。首拉、重试、同范围刷新与新频道切换区分；新范围取消旧请求，迟到结果不能回填其他频道。同范围刷新失败保留最后确认的实体。

频道合法标签、默认标签及关注关系变化后的校正统一来自 `domain/channel-detail.ts`。未知关系在首拉状态表达，收藏不派生为关注；关注、取关及实体回填后，所选标签都必须属于当前合法集合。

Twitter 频道热门集合由 `store/channel-featured.ts` 独占。首拉与追加继续使用 `notes/featured` 的 `channelId`、`limit`、`untilId`；刷新在请求局部确认已加载窗口，成功后才替换唯一确认集合，失败保留现有条目。删除事件撤下确认条目，并防止已在途响应重新插入。原界面的热门分页器继续服务原界面。

个人资料帖子使用 `TwitterUserTimelinePaginator` 作为每个标签的唯一分页所有者，继承原分页器的分页能力。首拉保持原有骨架与错误契约；同查询回访刷新保留已有条目，并在确认已加载范围后同步替换。刷新失败通过局部提示重试，不把已有列表换成整页错误。原资料实体的 `loadUser(false)` 继续保留已确认资料。

资料列表翻页期间收到的刷新意图在查询所有者内合并，待当前分页结束后消费；排序、日期或初始锚点变化作为新查询首拉处理，不将旧范围误作当前结果。追加请求互斥，控制栏与回访调度共用同一所有者。

时间线、通知仍使用原流式连接、轮询、新帖队列和未读状态；没有新增“每次激活就 reload”的规则。切换查询范围或明确执行原有全量刷新仍可能展示局部骨架。本文不将这些原分页器宣称为保留结果的全量刷新实现，也不通过停止刷新降低数据新鲜度。

## 代码预加载

`ui/twitter/routing/index.ts` 集中提供正式加载与预加载共用的动态 loader。频道和个人资料并行预热外层路由及内部 Twitter 展示模块，通知预热外层页面。时间线已静态导入，不另行预加载。

Twitter 入口的鼠标进入、键盘聚焦和指针按下只触发代码预热；同任务合并，失败释放记录。点击沿用 `MkA`，不等待预加载，不提前调用实体／列表 API，也不建立业务缓存或第二套路由表。没有启动时全量预热或组件内网络环境探测。

## 验证

`twitter-navigation-loading.spec.ts` 通过隔离真实后端覆盖代码等待、实体与列表等待、失败重试、合法标签、资料列表回访、刷新跨越原窗口末标识、翻页在途修改排序及注册入口。传输闸门只延迟原请求，放行后继续真实响应；从点击前逐帧核查出口背景、非空展示及 Shell／滚动宿主身份。各阶段截图是待审阅回归证据，不自动更新正式视觉基线。

既有 `twitter-profile.spec.ts`、`twitter-scroll.spec.ts`、`twitter-communities.spec.ts` 和 `twitter-write-freshness.spec.ts` 分别继续覆盖资料、滚动、频道交互及写后新鲜度。业务结果由真实后端回归证明，路由出口 unit test 只证明展示插槽与组件加载协议。

选择理由与历史方案见 [ADR-0018](./adr/0018-navigation-loading-continuity.md)。
